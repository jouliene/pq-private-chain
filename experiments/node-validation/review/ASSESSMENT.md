# Independent review of payment validation

The reference is public commit `7c2d0fc8b68c566d13e3e341c1f49bacaad527f4`. The calculations below use the registered ordinary two-input, two-output CP03 circuit. The owner's input is 100 million offers per year. The tenfold body comparison and the home-node, wallet and burst profiles are research scenarios.

## Masked relation and source correspondence

The lowering assigns wire zero to one, the next 49 wires to the canonical statement's public AIR projection and 296,448 to the original trace. Another 316,084 private wires are products of linear forms. Therefore enforcing base-field membership on the trace and using base constants/public values enforces it inductively on the product wires. The original lowering has 614,387 rows and 612,532 private wires. In the conservative homogeneous extension lift, each free trace word needs 63 further intermediate values and 64 squaring equations in this construction. Wire the last square to the 32nd square. The equality holds for zero and, for nonzero inputs, precisely when the multiplicative order divides `2^64−2^32 = p−1`. These are exactly the base-field elements. This lift has 19,587,059 rows and 19,288,756 private wires. It provides a comparison for one faithful encoding. The 356 active native permutations permit a different lowering, and each uses 152 seventh-power operations.

For the proposed four-challenge guard, draw all four uniform base-field challenges after the initial oracle and before any masked reply. Tie the returned canonical base value in each equation to the four corresponding coefficients of the final joint form. A malicious codeword may contain arbitrary extension-field blinds. A nonbase trace word gives a nonzero polynomial after projection onto some coordinate of the quotient of the extension by its base field. Its degree is at most 296,448. Powers must start at one so the separate blind occupies the constant coefficient. Independent roots of these four polynomials have probability at most `(296448/p)^4`, or 183.2903 bits before taking the union over the pre-challenge list. Distinct post-response batching adds a degree-seven term over the extension field for each candidate. This is an interactive calculation for standard independent verifier coins.

For an honest base witness, the four independent base blinds make the four replies uniform for each fixed challenge vector. The three terminal masks must cover the full extension ring. The earlier round messages also share randomness with the terminal claims. A plausible interactive simulation draws the challenges and four base replies first, then uses consistent auxiliary blinds and the paper's independent outer masks. It must also simulate responses from the same encoded oracle conditioned on those values and establish freshness for the code switch. The paper's simulator specifies its allowed oracle observers. The new guard, its oracle layout, the compiled salted commitments, challenge sampling and adaptive Fiat–Shamir/QROM experiment still need a joint correspondence and extraction analysis. ## Nonuniform schedule check

`python3 -I experiments/node-validation/review/schedule_check.py` independently computes the rows in [schedule-check.json](schedule-check.json) using 75-digit decimal arithmetic. The full-frame fixed part is 4,876 bytes. All cases use the guarded dimensions, four folds per nonterminal stage, 256 main symbols at the terminal, 40-byte EF5 symbols, 64-byte SHA3 digests, zero grinding and Johnson slack 1/4096. Every row recomputes query misses, list sizes, correlated-agreement terms, algebraic batching and subfield guard. The minimum idealized interactive exponent in these listed cases exceeds 129.9. An occupancy calculation prices exact expected multiproof frontiers for independent uniform samples with replacement. The maximum also accounts for the most widely separated feasible positions. Both sizes assume the specified implicit grammar, requiring a protocol decision on wire identity. Neither is a measured proof.

The burst row retains the specialist's separate salted-tree grammar and uses a first codeword of 2,097,152 columns of 16 symbols. Its RS dimension is 65,600. Four stages in total require 2,350,907,072 bytes for complete values, all separate-tree nodes and all salts. This leaves 1,944,060,224 bytes in a 4 GiB wallet scenario for the circuit, prepared matrices, keys, FFT scratch, allocator and process overhead. This accounting permits a test of assembling such a wallet. It gives no actual peak memory or completion time. It satisfies the 275,881.97 B block-only link case even at maximum size within this wire model. The same body exceeds the 137,682 B mean ceiling for the active-mempool-plus-block scenario. Both are role-dependent.

The paired scenarios move the terminal fresh mask to the last code-switch commitment, jointly hash both values at each position, and reconstruct the inner sumcheck's linear coefficient as in Section 11.1. Appendix B also discusses omitting salts under a classical random-oracle residual-entropy argument with one additional seed. The two positive tenfold sensitivity rows above keep salts. The extreme scenario even retains separate trees and all inner coefficients. Its storage makes clear why optimizing wire bytes alone selects an implausible wallet workload. Changing rates by stage and shrinking decoding slack produced these counterexamples to a family-wide negative size claim. The paper permits independent stage code lengths. These results do not establish implementation feasibility of the entire construction or project this success onto the other roles. ## Transparent block verification

`python3 -I experiments/node-validation/review/merkle_work.py` parses the two immutable ordinary public CP03 bodies. Each distinct per-query salt tuple certifies at least one distinct opened leaf. A one-root pruned binary tree with L distinct leaves and S supplied frontier digests needs L+S−1 binary parent nodes. The reference uses a 72-byte SHA3-512 rate and separate length/domain frames. The eight equal-height quotient chunks share a leaf hash. In a folded tree the guest reconstructs one omitted EF5 child, and the hash absorbs both children and the salt.

These are lower bounds on Keccak-f[1600] applications for the reference tree reconstruction per payment, excluding transcript and algebra. A verifier-owned precomputed fixed table may replace its fixed opening path at an independently accounted cost. The two fixtures deliberately share a nullifier. They provide two size/work observations and cannot constitute a valid two-payment block.

At upstream revision `1cc70cf05033a79ebc90f07c679cb4bd1cd301b9`, the Keccak circuit supports powers 14 through 18 and accepts floor(2^power/200) states per batch. Thus 37,317 permutations would need at least 461 batches at power 14, 57 at default power 17, or 29 at power 18. Segment count and proving time can differ sharply with geometry, hardware and parallelism. A real seal for 67 states authenticates a single component. The host still derives those states itself and checks their digest. A full guest would have to bind them to the CP03 proof parser, sponge path, ordered block claims, state transition, approved program and the complete verified receipt/assumption set. The pinned proof library uses 50 queries at inverse rate four. The idealized FRI query term alone is 100 bits. The vendor's v3.0.6 source targets 97 conjectured bits at its specified segment size. A numerical security claim for the entire CP03 construction is also open. Aggregating a receipt across multiple payments can reduce canonical link and storage costs even when its gross size exceeds the one-payment screen. Builders still need the full public CP03 authorization proofs and must process them at the offered/included rates. Independent nodes need sufficient authenticated block data for their own spentness, exact fees, state transition and rollback, while recovery needs available ciphertext and commitment history. A nonhiding outer argument can preserve the privacy of already-public CP03 artifacts by post-processing. Existence of an accepting computation needs a soundness/extraction composition tying it to an actual acceptable inner proof. Failure of stock parameters or one CPU accelerator allocation would leave other transparent protocols and hardware untested.
