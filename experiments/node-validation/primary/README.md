# Masked constrained-code primary experiment

A fresh process verified a genuine small masked R1CS proof over the CP03 quintic extension. Both retained proof files include the complete outer and inner transcript and authenticate every opened column. The full ordinary 2x2 CP03 relation has a separate executable parameter and byte projection. That projection meets the researcher-selected block-only link in some profiles. No complete masked CP03 payment was generated here. Payment prover resource use, concrete non-interactive knowledge and joint privacy remain open.

## Two executable statements

The base field is Goldilocks, `p=2^64−2^32+1`. Extension elements are five canonical little-endian words in the power basis modulo `X^5−3`, matching the retained [field source](../../../source/experiments/compact-challenge-v1/view01/goldilocks/src/extension.rs). Challenges and all inner/outer mask coordinates use the entire extension. RS points in the tiny probe are the 64 distinct nonzero base elements 1 through 64. The projected power-of-two domains instead use supported multiplicative groups of the same field.

In the first public circuit two private bits have the public sum one. The second circuit checks `x+y=b` and `(x+y)^2=b`. Its required base-field inputs use the probabilistic guard below. At `b=1` the latter circuit alone admits `x=u, y=1−u` for arbitrary extension elements. The public verifier owns the choice of circuit, all dimensions and the public sum. The two proofs were generated by separate processes using fresh secret randomness. Their sizes are 5,320 and 5,736 B, respectively. All 33 and 37 nonempty transcript regions rejected one-bit changes, and both rejected wrong public input, a short proof and extra bytes. The first failure can arise from changed Fiat–Shamir challenges before the edited section's intended downstream algebraic check. No private assignment, keys or random seeds were preserved.

`probe.py` implements the honest prover and public transcript verifier; `field.py` and `transcript.py` implement the arithmetic and canonical byte transcript. A verifier process takes a proof, an approved circuit selector and a public input. Proof parsing neither invokes the prover nor reads prover fixtures. These research routines have no constant-time or side-channel qualification.

## Guarding the subfield efficiently

The conservative full lowering imposes `x^(2^64)=x^(2^32)` on all 296,448 private trace words in EF5. This costs 64 squares, including the final equality output, and 63 additional intermediate private words per trace word. The alternative retains the native circuit and reserves four more auxiliary coordinates in the *same* initial randomized codeword.

Before the verifier samples the guard challenges, the honest prover commits four independent uniform base-field blinds `t_j` with the witness and outer masks. The verifier then draws the entire vector of four independent base challenges `b_j` in one round. Before the outer sumcheck, the prover sends four canonical eight-byte base values `y_j=t_j+sum_i b_j^(i+1) w_i` for the fixed, ordered set of trace-input indices starting at zero. There is no intervening prover message between challenge draws. Include all four linear equalities in the final EF5 form using powers of the single post-answer batching challenge up to seven. Each blind receives the coefficient of its own claim. This exact layout is exercised for two source words in the guarded circuit.

For any fixed decoded message containing a nonbase source word, pick a nonzero quotient component of the witness vector in EF5/Fp. The corresponding nonconstant scalar polynomial in b has degree at most the number of tested words. An arbitrary fixed extension-valued blind contributes only the constant term. Four independent b values therefore permit all four true contractions to be base with probability at most `(296448/p)^4`, before multiplying by the pre-challenge list size. If a supplied base value differs from its actual contraction, the nonzero joint discrepancy survives the subsequent random combination except with probability at most `7/|EF5|` per current list entry. For an honest witness, each base output is uniform conditioned on all b and the witness, thanks to the independent blinds. The strong query-private encoding hides queried symbols conditionally on the expanded message, and fresh outer/inner randomness must be used for every proof. A complete formal analysis of the modified reduction and its non-interactive compilation remains open. This change adds four base challenges, 32 proof bytes and roughly four traversals of 296,448 coefficients for each side. Four base seeds generate all coefficients through public powers. Five or seven independent tests are used in the 192/256-bit interactive sensitivity.

A deterministic control checks a genuine nonbase assignment satisfying the unguarded field circuit. Its quotient polynomial is `b−b²`, with exactly two roots. Exhaustive enumeration over a small base field covers every nonconstant degree-at-most-two projected polynomial including all possible blind constants. The measured maximum is two roots among seven points, giving 16 out of 2,401 challenge vectors with four fresh coordinates in that toy. The explicit degree bound supplies the large-field argument.

The payer's 528-byte canonical statement and both complete encrypted receipts, 4,328 B, are charged along with a 20-byte body frame. A separately named copy of the statement costs another 528 B at interfaces that require it.

The selected stages occupy 1,744,830,400, 1,744,830,400, 872,415,168 and 121,634,688 B each when retaining all values, salts and nodes. All stages together use 4,483,710,656 B. Stage-by-stage proving can discard the old oracle after its authenticated query rows are recorded. The two largest adjacent stages consume 3,489,660,800 B before application witness, matrices, allocation overhead, FFT workspace and auxiliaries. Streaming a single row of the first stage requires an 80 MiB in-place transform. A full unpruned radix-two FFT schedule uses 22,020,096 butterflies per first-stage row and 877,133,824 across all oracles. Those are operation counts for that particular algorithm. Pruned or coset FFT implementations and disk trade-offs need measurement. Storing less than a full matrix requires recomputing or streaming public matrix coefficients. The fresh verifier must evaluate the true sparse-matrix and auxiliary forms at its folding challenges. A root-opening check alone does not perform this work.

With four independent guard challenges the selected interactive error estimate is 130.20 bits; the list-charged guard contributes 175.56 bits. The experimental block-only 100% inclusion / 16 Mb/s / tenfold 600-s burst / 3,600-s drain threshold including the [role framing](../roles/project.py) is 275,881.970 B. Of the 1,188 wide **uniform** geometries examined per strength, 189 at 128 interactive bits meet that expected-byte screen, and none at 192/256 do. Allowing each stage to choose its own rate improves the joint memory/bandwidth frontier. This is not a universal impossibility result. The separate reviewer explores the paper's optimized Section 11 layout and different Johnson slack. A full-scale isolated wallet proving run and independent CP03 verification are needed before promoting any profile.

python3 -B probe.py verify toy-public.proof --controls | diff -u toy-public.json -

python3 -B probe.py prove "$tmpdir/fresh.proof" --guarded
python3 -B probe.py verify "$tmpdir/fresh.proof" --guarded --controls
python3 -B controls.py | diff -u algebra-controls.json -
python3 -B budget.py --rows 614387 --private 612532 --public 49 --base-inputs 296448 | diff -u cp03-budget.json -
