# SLG1 prepared leg

A leg consumes one or two notes from a single wallet, including real slot zero. The verifier proves the same private spending authority and funded membership for each real input as AST1. Each native and token quantity is bounded to 62 bits. Native inputs equal native outputs plus the leg's fee, which is restricted to 0 or 3. Token inputs equal token outputs under one private transaction ID, a nonzero four-limb ID when there is a positive token quantity. Dummy inputs contribute zero value in both lanes. Any zero token quantity uses canonical zero ID. No supply operation exists in this circuit. The outer transaction must settle both legs with a total fee of three and four distinct nullifiers and funded commitments against acceptable anchors.

The proof's statement has the existing 26 public words (anchor hash, anchor height, two nullifiers, two commitments, fee and digest of both ordered receipts) followed by eight 32-bit little-endian limbs that exactly encode the ephemeral 32-byte authorization key. Each output derives its effective raw opening by Poseidon2 over field domain 0x534c47310001, those eight key limbs, and four independent raw randomness limbs. AST1's type-hash domain 0x415354310001 takes the per-note ID, quantity and that effective opening. The inherited commitment and nullifier rules use the resulting typed randomness. Each encrypted output opens to the effective raw value; decoding and spending use unchanged AST1/MNG1 code and need no private preimage of the output-randomness hash. Input openings use those longstanding AST1 rules without applying the extra hash to the input again.

The key occurs in the verifier-checked statement and in the preimage for each typed output commitment. Preserving a fixed funded leg while replacing the public authorization key would require a false proof or a colliding opening. A spender who creates a fresh proof for their own inputs can choose their authorization key and different outputs. Such a proof has a different packet digest and needs fresh authorization by both participants for a new joint body. The verifier takes no key, program, or circuit selected by a counterparty.

A prepared SLG1 packet contains ASCII SLG1, width byte 1, u32-LE proof length, the complete proof and two 1,792-byte ciphertexts in order. Slot zero pays the counterparty. Slot one pays change to the payer. The verification service returns ASCII 1, anchor32, height4, two nullifiers and two commitments (32 bytes each), native fee8, two ciphertexts and the ephemeral public key32. Single-leg admission is absent from the ordinary AST1/MNG1 payment rules. This program is a separate registered role. The node owns the outer SWP1 packet, chain authorization, conflict/expiry checks, double-spend rejection and atomic commit.

The wallet selects a fresh private random nonce of 32 bytes per leg. The ephemeral signing seed is SHA-256(ASCII SWP1/leg-auth-seed/v1 || NUL || private spending seed32 || nonce32), passed to pinned Qnero's deterministic SLH-DSA-SHAKE-128f implementation. Its 32-byte public key enters the leg proof. The wallet signs the canonical outer authorization digest only after verifying both leg proofs, checking the exact local terms, opening the counterparty's receipt to its spending-derived public key and checking its own change. With that authorization a submitter may deliver the complete joint transaction during the permitted interval. Aborting a peer interaction cannot revoke a signature already released. Expiry, branch policy and ordinary input conflict govern later settlement.

The local wallet IPC retains D to open a note. E || nonce32 returns the prepared public key. P || nonce32 || fee byte || header132 || native u64 || token u64 || asset32 || destination1601 || count byte || compact sources returns the proved leg with both receipts. S || nonce32 || joint digest32 returns a 17,088-byte signature. The verifier IPC accepts a prepared packet, or V || key32 || digest32 || signature17088 and returns ASCII 1 or 0 for the signature verdict. All IPC frames use a u32-LE length. Only the trusted local wallet process holding the private seed serves D/E/P/S. Its D command decrypts, recomputes the exact output commitment using derive_pk(ask,nk) from the spending seed, and derives the real nullifier with the same nk. Before inclusion a recipient can check authority and note data; selected-chain membership is obtained only after admission. Neither D nor successful proof verification by itself approves the publicly offered exchange terms.

This design retains the existing blinded Plonky2/Goldilocks D=2 parameters and receipt privacy assumptions. Malicious-payer receipt failure is checked by each local participant before signing. The distinct SWP1 envelope and fixed leg roles are visible to observers. Formal joint proof knowledge, noninteractive quantum soundness, multi-user recipient anonymity and unlinkability under external timing or disclosure remain open. Fresh signatures and proof randomness do not mask reused real nullifiers or a retransmitted packet.
