The command builds both K384 roles, recreates their pinned keys before producing proofs and opens only new fixture storage. Use `--target "$existing_cargo_target"` to reuse a compiled dependency cache. The default is a new target in the run directory. Read the exact local binary hashes from each fresh build. Absolute source paths can affect binary identity. Both verifier source manifests and binary pins are operator inputs.

The matched run saves both participant seeds before funding. Two separate issuers use the original MNG1 registration and proof machinery. One issues 70 fixed units. The other registers 300 managed units under its issuer key, signs the authorized +40 mint using the previous registered event and sequence, and spends funded notes to burn 10. The checker runs the deployed source's selected-history supply rules against an isolated in-memory SQLite registry, verifies both authorization signatures using the MNG1 public process, and obtains 70 fixed / 330 managed. The decoded MNG1 notes, fee amounts and public openings retain the live rules. Funding leaves give Alice 20 native + 15 fixed in one mixed note and 9 more native in a separate note. Bob receives 18 native + 80 managed in a mixed note and 9 independent native units.

Alice's candidate leg consumes her mixed input and pays 7 fixed. Its change contains 17 native + 8 fixed after the three-unit fee. Bob's leg consumes his own mixed note, pays 30 managed with zero fee and returns 18 native + 50 managed. Both have one real and one dummy input, matching the published SWP1 walkthrough. Both owners check the expected incoming receipt using a spending-derived key and verify their change before releasing independent 17,088-byte final signatures. After joint verification and admission to the fixture's test inventory, brand-new wallet processes open the incoming notes from the backups saved before funding. Alice's K3M1 ordinary payment consumes her received 30 managed plus her independent native fee note. Bob forwards the received 7 fixed using original MNG1. The forward recipient opens the K3M1 output and spends its 30 managed again using the original verifier. Each amount, tag and consumed nullifier is checked. The first exploratory run used two fixed assets (7/11) and two real inputs for each swap leg. Its measurements are separate from the matched run.

Merkle roots use pinned Qnero hash rules; the fixture tracks spent nullifiers and applies the successful pair locally after checking both proofs, both signatures and distinct effects. It validates the enumerated positive path. The public inventory has synthetic rewards and anchors, fixed context height and isolated registration state. It does not mine PoW, implement transactional rollback for arbitrary invalid inputs, establish an active consensus upgrade or admit oversized packets to a live network. Ephemeral wallet seeds remain under private tmpfs. The verifying processes mount only the executable, libraries and approved public keys. Native timers cover setup, proving with generation of both ciphertexts, verification and each final signature. Public checks include altered signed terms, corrupted receipt, modified public fee and changed proof bytes. No check publishes raw private wallet IPC.

The published ordinary experiment envelope is K3P1, byte 1, transfer byte 0, then the complete K3M1 packet. The K3B1 bundle includes two K3F1 frames containing K3L1 leg packets, exactly analogous to live SWB1/SWF1/SLG1 framing with separate magics and SHA-256 domain K384/joint-authorization/v1 followed by NUL. The experimental decoder permits 2 MiB per physical frame so costs can be measured outside the chain. The actual live bound remains 262,144 bytes. The authorization digest retains 256-bit SHA-256, the established one-time signing scheme and a separately domain-tagged test network. Both recipient encryption and spend/note commitments retain all their assumptions. The current private inventory cannot obtain stronger cryptographic binding merely from re-proving the same values.

The pinned native challenger uses the commitment hash's permutation type; the constrained public-input hash continues to use the original algebraic InnerHasher. Here SHA3-384 separates general field hashing, leaf hashing and internal nodes. SHAKE256 separately maps the complete state to canonical Goldilocks words by rejection sampling. SHA3-384 and SHAKE256 are standardized primitives.
