# A funded-note frontend for a different proof system

**The legacy membership hash can be expressed directly in the historical WHIR frontend's base field.** We compiled the sorted four-child Poseidon2 parent compression into ordinary rank-one constraints over Goldilocks. The positive fixture used the four actual published output commitments of the baseline swap in a new test tree. An independent, unmodified Qnero full-tree binary supplied its public root. The assignment satisfied every row and changing the expected public root failed the same relation. This measures field compatibility and the cost of one necessary component for keeping funded notes. The fixture is a new four-leaf tree. It does not assert that these four commitments occupied adjacent positions in the live ledger. [Executable lowering](whir_port.py) · [Measured result](WHIR_PORT.json) · [Independent reference source and build](../advancing-payments/review/REVIEW.md)

The pinned additive sponge absorbs 16 words, then pads and processes a third eight-word block. Each of the three width-12 permutations uses 8 full and 22 partial rounds, or 118 seventh powers per permutation. This implementation uses four multiplications per seventh power. Intermediate affine layers are explicitly materialized so that the circuit does not acquire exponentially large expressions. The result contains 1,416 S-box multiplication rows and 1,120 affine or output-equality rows, 2,536 total. Matrix A/B/C have 15,226/3,244/2,536 nonzero coefficients in this encoding. For two maximum-depth 20 paths the 40 parent evaluations account for 101,280 rows before the two private positions/level selections, active-depth controls, note openings, nullifiers, monetary arithmetic, statement projection and swap key. This is a count for this encoding, independent of any WHIR proof-size estimate. It is neither the size of the complete relation nor a claim of optimality. The circuit shape is independent of the children and root. The inputs in this probe are in the protocol's presorted order. Full private path selection still needs its verifier-owned constraints. [Upstream membership source](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/merkle.rs)

The earlier guarded WHIR wallet verified full native-only CP03 payments in a different relation. It used a Goldilocks base, a quintic-extension challenge, 64-byte Merkle digests, different depth-40 occurrence rules, note encodings and receipt binding. Three full historical bodies were 264,108, 263,084 and 262,684 bytes. Their sizes are evidence only for that historical relation. The CP03 verifier will not validate an MNG1 or SLG1 payment, and a direct substitution would strand old notes. The current comparison demonstrates a route to preserving the actual funded hashes. Extending the frontend and mapping the entire masked sumcheck, guard, terminal opening and noninteractive compiler to a concrete joint hiding/knowledge argument remain necessary.
