# Versioned token and exchange path

APV2 validates the ordinary two-input/two-output native transfer under the registered wallet and occupancy keys. Its public inputs have no authenticated asset type, exchange agreement or role. Two independently paid ordinary transfers can occupy one atomic block, and one invalid transfer invalidates the block. Either ordinary payment is also valid by itself if eligible. **A pair of ordinary payments therefore cannot enforce an exchange.** The two proposals below need new relations, wallet formats, verifier keys and consensus activation.

| Candidate type | Relation to register | Smallest selectable unit |
| --- | --- | --- |
| APV2, current | Native payment under the installed ordinary proof system | One independently valid payment |
| APT1, proposed | Versioned asset notes, transfer authorization and native fee | One complete token/native-fee payment |
| APS1, proposed | Matching private exchange agreement with two role proofs and joint verification | One complete agreement, consuming two effect slots |

A future network must select a closed table by genesis, deployment and activation height. Bind network, deployment, version, operation, verifier-profile identity, canonical statement and anchor to each proof, recipient receipt and outer slot. Reconstruct every statement from the canonical body and verified public effects. Refuse unknown versions, unmatched lengths and trailing bytes. Under APV2 alone the production dispatcher rejects both new types. Both the future singleton and aggregate verifiers need separate registrations for their allowed public shapes. A manifest name supplied by a sender cannot authorize a new relation. A local typed layout is preliminary work only.

## Private token transfer and native fee

An input opens a typed note and proves its membership, spend authority, unique global nullifier and asset/amount range. A note commitment binds versioned encoding, provenance, asset, amount, one-time recipient authority and blinding. The receipt carries the same opening and asset to its recipient under authenticated encryption. For each distinct input/output asset `a`, enforce checked integer conservation `sum(inputs[a]) = sum(outputs[a]) + (fee if a == NATIVE else 0)`. Private identifiers require a complete constrained grouping/equality or equivalent multiset proof. Checking one chosen asset leaves the others unconstrained. Canonical ranges and carry bounds prevent field wrap. Charge the bounded native fee once from native value. A payer without native fee inputs cannot use this proposed transfer unless an explicitly authorized, separately constrained sponsor relation is added. Define sufficient note slots for both assets and changes, and hide unused slots before committing to cardinalities. Token amounts and IDs need not appear in the public selector. Specify separate, bounded issuer/mint/burn operations and supply policy before enabling issuance. Reuse an underlying note's spent identity across all legal consumption versions, including any native-note migration bridge.

## Two-owner exchange

Each participant supplies a hiding proof under its registered role circuit. Each role proves authority over its own inputs. Participant A and B each approve both ordered sides of the same agreement before exporting a role proof. The agreement binds the network/version, fresh joint salt, expiration, owner authorization commitments, ordered assets and amounts, both agreed payees and change rules, native fees/payers, and a canonical core effect commitment for each participant. Define a noncircular core that omits agreement-dependent receipt tags and proof bytes. Each final receipt, role and statement then binds the completed agreement. Use hiding commitments when terms are private. A digest of public low-entropy trade terms can be exhaustively guessed. Define timeouts, expiry and resubmission from the current selected history. One party may refuse to finish before inclusion.

The joint verifier checks exactly one role of each kind, a common approved agreement, both authorized transfers to the specified opposing recipients and native fee charges. Each owner contributes an authorized, bounded debit and receives the negotiated credit; per-asset joint conservation alone could pay two wrong recipients. The registered singleton/aggregate statement authenticates both sets of nullifiers, receipt/effect commitments and the indivisible type. Each underlying note version needs an explicit spending path. An APS1 child must never be admitted under an ordinary singleton rule. A producer that has both child proofs must still deliver both role effects as one atomic item. Public matching commitments and the two-slot size can link counterparties' packets and reveal exchange activity; an anonymity claim requires a specified observer and privacy analysis. Owner control can be proved under distinct authorities; the protocol cannot prove the owners are two distinct human beings.

At selection, relay, block verification and reorg replay consume the typed atom in full or reject it. Apply both sets of effects and fees in one DB transaction after genuine proof verification, current nullifier and commitment uniqueness, independent fresh anchor tests for each role, expiry and authorization checks. On rollback undo the whole atom, and revalidate the whole retained candidate on the new branch. Partial legs cannot enter through an ordinary fallback, a batch residual slot, separate blocks or replay of a single receipt. A two-slot atom can wait for the next block when only one slot remains; sparse ordinary submission still accepts singletons independently.

## Executed boundary

The Python model exercises public construction, FIFO packing, block shape and suffix replacement. It binds the proposed ticket digest to the kind, ordered roles, agreement, effect and nullifiers. Its output is a candidate layout only. No API verifies a proof, executes transfers or updates a ledger. Someone can recompute every synthetic digest; only future registered proofs can authorize these statements. The examples exercise typed grouping and transaction-boundary rules using public synthetic values, and intentionally exclude wallet/proof performance, private algebra, recipient encryption, funding and consensus finality. The published preceding native profile put two real ordinary wallet payments in a 157,220-byte pair, then opened and respent received notes. Its verifier rejected a changed proof, fee or ciphertext, truncation, an extra byte and replay. That measured pair used the earlier native proof parameters. APV2's current ordinary protocol and integrated campaign provide the distinct fresh proof, DB atomicity and selected-branch evidence.
