# Advancing payment experiment, version 1

The prior CP03 and WHIR wallet remain reference profiles. This separate native version accepts only source-registered ordinary 2×2 receipts with two nullifiers, two commitments and one bounded native fee per real slot. The wallet uses an inner nonhiding proof privately and exports only a blinded wallet proof. Occupancy one is independently verifiable directly. Occupancies 2–4 aggregate the finished wallet proofs; each slot retains its own anchor and public effects. Each node supplies its verifier keys. The research comparison uses the same stronger registered settings for all layers, fixed before proving, with independent source correspondence and explicit limitations in assurance/.

Genesis bytes are `APGEN001 || u32le(N) || N canonical 32-byte funded commitments`. Funding is a separately approved local endowment, uniquely bound by its SHA-256; a node that reopens an existing DB must supply the same approved genesis. The selected local chain begins at height zero. Network identifiers, versions and oracle domains belong to this experiment only. At prospective height H a payment at h must pass 1 <= H-h <= 8 and match the exact registered block ID at h on the current selected branch. Current nullifiers and commitment uniqueness are checked across all participating slots and all earlier accepted blocks. The entire block commits or rolls back in one SQLite transaction. Branch switching undoes the old suffix and validates the replacement in one transaction. No automatic permissionless fork choice is claimed.

A block is `APBLOCK1 || Header132 || u64le(nonce) || u32le(packet_length) || packet`. Empty blocks are permitted in the local clock. A header contains parent ID, height:u32le, state digest, body digest and the funded quaternary root (32 bytes each except height). The registered Qnero header hash uses the fixed all-zero digest logs. Body and state digests are domain-separated SHA3-256 over length-framed parts with counter rejection for four canonical Goldilocks limbs. The body digest binds nonce and complete packet. The state digest incrementally commits to the previous state, total count/fees and the ordered public transition. The commitment tree authenticates membership; its sorted child hash requires the separate ordered transition/branch identity. The nullifier and unique-commitment indexes serve current admission and must persist even after body pruning. A trusted local node's own previous state supplies the frontier. No caller-provided public frontier can bypass genesis or block replay.

This milestone measures local scheduling and validation with explicit block opportunities. A physical PoW network cannot guarantee a finite wall-clock confirmation bound at arbitrary hash rate, under censorship, or through a network partition. The duty of a direct producer is to admit an eligible singleton without a minimum batch size. Time bounds and measured load refer to the stated local service and successful endpoint.

The approved APV2 profile manifest SHA-256 is `af88a0ac0caa5f0aa27d38d687b6cc39495a0aa2659ed4a7e5e74653724cc1b1`. Its five layers were generated and independently decoded before author wallet creation. The node binds that manifest in genesis state and in the persistent database configuration. A single explicit rollback floor, the maximum selected height ever committed minus eight (at least zero), applies to both archival and pruned nodes. A shorter selected replacement does not lower the floor. A failed branch switch cannot advance it. The random test endowment supplies two positive real inputs for each generated payment. The upstream private circuit also permits a zero-valued dummy input slot.

The bounded experiment's normal underfill grace is 200 ms, with a 10 ms polling interval and a 3 s observed local singleton completion check. A direct ingress bypasses aggregation. The peer relay adds four bytes to a complete block. For the prepared busy stream, three groups of four arrive on a monotonic clock spaced at max(1 s,1.5 times the preliminary four-slot warm builder and validation wall time plus 0.3 s inside the factor). Long-run capacity needs other evidence. The low-load block mix for the role model is 85/10/4/1 percent of nonempty blocks by width 1/2/3/4, with one empty opportunity per paid block. The busy mix is 5/10/15/70, with one empty per nine paid blocks. These are researcher scenarios. One and five decimal TB/year are open comparisons.

A separate open-loop direct-service test schedules four intents from a single funded wallet at 0, 12, 24 and 36 seconds. An independent local block clock has a two-second period and accepts empty blocks while proofs are being built. The preferred endpoint is stopped and there is no aggregation process. The declared full-intent observation threshold is 22 seconds, with an eight-height eligibility window that remains in force. The clock records lateness on every block. This measures proof creation, real delivery, verification and durable inclusion with one sender active. The separate three-burst test loads prepared wallet packets and measures the builder/producer service boundary.

An additional discriminating experiment starts a warm arity-four builder using only four already produced wallet submissions, all at height zero, and an open-loop block period of two seconds. The first block contains a separate genuine payment. Each next opportunity admits the aggregate if it is available and still eligible; otherwise the independent chain advances with an empty block. The test verifies all four inner statements against the final public output even if the aggregate expires. CPU setup, prior wallet proving and waiting for sufficient independent senders are outside this optimistic aggregation window.

The main branch's recovered wallet had previously sent as well as received; its first recovered notes can be change. A separate clean receiver scenario funds only the sender at genesis. The receiver exits before the two payments, opens one output from each after seed-only restoration, and proves a new two-input spend using the only two available notes. After admission it opens one new change output on the updated history. Public replay separately checks all cryptographic authorizations and ledger effects; receipt ownership is a private wallet observation.
