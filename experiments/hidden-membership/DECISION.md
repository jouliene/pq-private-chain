# How should a private payment prove its two inputs were funded?

**Keep the authenticated occurrence tree and change how its hash computations are proved.** Retain C for funded money and N7P2 for wide-note comparisons. Hold both the generic SmallWood+ circuit and the global table lookup before payment integration. Only the first construction demonstrated two private opening-to-root paths in one argument. Its mixed-field proof for that relation alone costs 5,966,544 bytes. A wallet selecting from a globally compiled table instead pays costs that grow with branch occupancy. Neither warrants replacing the reference wallet or changing funded money. The proposed next experiment preserves private branch-derived membership and targets the measured byte cost directly.

## What the verifier checked

The source is Feneuil, Provin and Rivain's November 12, 2026 SmallWood+ paper, pinned by PDF digest. The two public predecessor repositories implement an earlier construction. We built Compiler 1's generic masked R1CS argument from the paper. It commits jointly to witness and trace masks, checks the sum-check terminal equations against that commitment and opens degree-tested columns. Our format sends individual Merkle paths. The paper's 63.1 KB for 100 Keccak CICO instances uses specialized round batching, bit packing, and different public endpoints. It gives no payment size or timing for our experiment. [Primary paper](https://eprint.iacr.org/2026/2880) · [Source and version correspondence](smallwood/SOURCES.md) · [Transcript and assumptions](assurance/REVIEW.md)

In the linked-parent experiment, a verifier fixes the expected 512-bit root and level. One witness selects either child order at each level, computes both complete Keccak parents, and routes all 512 hidden digest bits between them. The four order combinations passed at the calibration strength. A deliberately inconsistent assignment contained two individually correct hash computations. A new process rejected the resulting full-length proof against the correct public statement. Changed expected roots, levels and cryptographic opening data also failed. An independently implemented binary-circuit VOLE test exercised both outer child positions and the hidden intermediate. Its inner pair is already witness-ordered and it carries no owned-note claim. [SmallWood+ runs](smallwood/README.md) · [Mixed-profile controls](smallwood/mixed/evidence.json) · [VOLE control](control/run.py)

For the funded test, an isolated synthetic genesis pins eleven authorized native grants. Two fresh public fixed-supply asset registrations have independent SLH-DSA-SHAKE-256s signatures, supply caps and ML-KEM-1024 receipts. A recipient helper opens each receipt at creation. The prover opens one native and one issued note at different hidden indices in a shuffled private order. Each of the two openings derives its owner from ASK, commits to a typed note and binds the creation occurrence to both the funded leaf and the public nullifier. The same committed witness supplies both forty-level paths and bit directions. The circuit checks two distinct indices below the public count and fixes all subcircuit constants. A fresh verifier checks the genesis pin, issuer signatures and registration rules, then computes its own chain, count and root from public records. The pin, suite, chain, root, count and both nullifiers enter Fiat–Shamir. The fixture occupied 13 of the 2^40 positions. The public prefix discloses the grants and issues. Path depth determines capacity, while occupied count and observable funding policy limit privacy. [Funding roles and mutations](paths/test_funding_fixture.py) · [Circuit and copy constraints](paths/funded.py) · [Public verifier](paths/role.py)

The two valid funding orders produce different roots on the same genesis. A proof generated for one order failed against the other. A separate clear-equation control exchanged two intact valid paths while keeping both authorized openings in place. Only the two sets of opening-to-path equalities failed. The fully serialized dishonest proof test is on the two-parent component. The prototype verifies eligibility against one pinned prefix. Live PoW selection, recent-anchor policy, current nullifier uniqueness and atomic mutation remain duties of the application ledger. A rejected prefix, grant, issuer signature, cap or duplicate issue cannot create an eligible witness through the public fixture. A full relay to four peers multiplies the one-copy Mbps by four, and sending mempool and block payloads separately adds another copy per destination. At 100M the generic mixed profile alone would use about 698 Mbps for four outgoing bodies. The reference home scenario has two cores, 16 GiB, 2 TB storage and 100/20 Mbps access. A locally proving tree wallet can retain two private authentication paths of 2,560 B each plus a branch cursor, common frontier, notes and undo state. Public appends update affected paths. A backup restore must obtain common authenticated creations and scan the receipt stream for its keys. Forty siblings at a selected private index must never become a targeted public request. With the lookup, each proving wallet also needs the authenticated funded table, or a lossless equivalent. Its leaf stream costs 14.08 GB for the first 220M creations, and the padded coefficient table reaches 17.18 GB at year end and 70.37 TB at capacity. The shared receipt stream alone costs 394.24 GB at 100M operations, one tenth that at 10M. Full validated bodies can supply these projections without double counting their bytes. None of these candidates removes initial data availability, the obligations of archives or the metadata observed from wallet networking.

## Security decision and the next gate

The mixed port explicitly embeds the 16-bit field in the 256-bit challenge field, expands every large-field trace coordinate, and splits the random Q mask with an independently randomized coefficient overlap. Its test checks all base elements, the 256 basis coordinates, and every one of 16 trace positions. For the linked relation the interactive row term has exponent 251.91 and the column-opening and degree-test exponents are about 256.26 and 256.68. For the funded circuit the row term is 22/2^256. The 16-bit calibration has a large row error. Neither profile yields a quantitative 128-bit quantum monetary claim. The paper's extractor uses a chronological list of classical hash queries and answers. The inference to adaptive quantum Fiat–Shamir with multiple proof/receipt observations requires a corresponding extractor or a different, source-matched transform. More hash bytes by themselves do not supply it. A simulator for the complete joint view must include ciphertext key privacy, public retry nullifiers, anchors, funding metadata, swap approvals and later spending. The global lookup's VOLE signature ancestry also lacks a reduction for this complete ledger statement. [Applicable theorems, limitations and lifetime sensitivity](assurance/REVIEW.md) · [Registered receipt and retry games](../fresh-spend/binding/GAMES.md)

**Advance one structured Keccak wiring experiment.** Keep the occurrence, note hash, hidden directions and public root unchanged. Implement the paper's round-batched GKR with ring switching for two privately linked SHAKE parents. Commit to the private intermediate digest and both child placements in the same witness, verify both directions and open only the final 512-bit root. Measure complete proof bytes, wallet/validator resources and mask/rank checks on the two-parent statement before porting 80 parents. Evaluate the quantum extraction question on that exact transform in parallel. An executable packing reference checked 2,048 basis perturbations, all 65,536 selector-field candidates and 160 SHAKE comparisons, including two forty-level paths to the same root. It needs 32 base-field products per parent to select both children, or 2,560 plus up to 80 bitness products across both paths. Header spill, padding and the bit remapping are linear over GF(2). A proof must still link those bits to the GKR state across the extension-field boundary. These counts cover just child placement. [Packed transition reference and obligations](smallwood/mixed/README.md) · [Reference counts](smallwood/mixed/packed-evidence.json)

The early discriminator is whether round batching removes the per-AND committed witness cost with the private interface, while preserving correct domain, padding, hidden link and a potentially defensible hiding argument. The general R1CS cost and the global table bottleneck each have a concrete mechanism that this experiment changes. No migration of C funds is proposed.

## Reproduce

On x86-64 Ubuntu 24.04 with CPython 3.12, NumPy 1.26.4, GCC, OpenSSL development headers, CMake, curl, GNU time, PCLMULQDQ and SSE4.1, run the following from a clean checkout. Use a new scratch path. The runner checksums public dependencies, rebuilds the comparison library and native arithmetic, generates fresh funding and proofs, verifies changed statements, and regenerates the prices. It writes public test records and measurements to scratch. Private funding openings move only over process pipes.

```sh
bash experiments/hidden-membership/reproduce.sh "$(mktemp -d)/run"
```
