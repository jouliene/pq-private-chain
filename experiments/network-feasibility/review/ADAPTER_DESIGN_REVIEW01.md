# Network04 adapter design review 01

Disposition: additive versioned direction is suitable for implementation review, subject to the exact conditions below. This is not a source freeze or execution acceptance. Reviewed against baseline d8f8000 ledger/history/wallet source; no native command or proof run.

The proposed CPGEN004/schema3, CPBLOCK4 and CPNET004/CPSBLK04 keep CPBODY03, full payment AIR, proof/profile/program identities, receipt/source algorithms and fees unchanged. Count0..128 plus an independent256MiB encoded cap is coherent. A full frame is `228 + 68*n + sum(body_lengths)` bytes, including magic, header length, 216+64*n header and n length fields. Empty full frame is228bytes. Some128-body blocks with individually maximal bodies exceed256MiB and must reject; count cap is not a promise all capped bodies fit.

## Material conditions sent before implementation

1. **Empty history and wallet bounds.** Baseline recovery.mjs flushes only on256payments and immediately returns from applyWindow when payment count is zero. Empty-block support therefore creates an unbounded window; an all-empty or trailing-empty stream also fails to advance the applied cursor. Bound block count independently of payment count, process empty cursor transitions without a crypto helper request and preserve the bounded common-history mechanism. Empty blocks must preserve root/count/fees/liabilities, while height/parent/head/anchors advance. Test empty prefix, middle, tail, all-empty and more empty blocks than the buffer bound. Genesis-empty context must establish the correct empty root if exposed to wallet consumers.
2. **RETAIN means a real persisted local policy.** Baseline body_cache_insert always increments unexported_bytes and creates archive_pending. Merely declining export cannot be reported as zero outstanding export work. An explicit persistent policy must define locally retained full bytes, pending semantics and prohibited eviction; preserve archive-required behavior on legacy/tiered databases. Open/restart must not silently change the policy. Even with zero export obligation, charge all bodies, reduced duplicates, SQL indexes/tree/undo/WAL and any archive role bytes. Hard capacity still backpressures before mutation. Changing retention policy is not a consensus/genesis vote.
3. **The committed byte total must be reconstructed.** Check the exact full-frame length against the header before allocation/commit and against each canonical body's actual length. Reduced history can independently reconstruct it from prefix length plus the embedded proof length; validate that equality in Rust and wallet decoders. A cap on the claimed u64 alone is insufficient. Body hashes already bind that prefix/proof digest; no new proof or fee formula follows.
4. **Version selection is not per-message negotiation.** Genesis selects the allowed block/history/schema policy. Reject legacy genesis with Network04 blocks and Network04 genesis with legacy blocks, including mixed scan streams. A syntax-only generic dispatcher may parse both, but no caller may treat it as chain-policy validity. Legacy public checks/fixtures must retain their byte identities and semantics.
5. **Empty versus missing undo.** Existing tree::restore rejects no undo rows and caps1312nodes. For Network04 allow zero undo only when the authenticated block is empty; do not waive missing undo for nonempty blocks. Increase the nonempty safe bound coherently to at most256*41=10496 touched-node rows with a sentinel query, preserving checked/canonical state. Empty rollback must restore parent state/anchors and support repeated root/count pairs. Anchor eligibility remains root/count-based: repeated empty roots do not constitute an expiry test.

## Additional persistence and framing controls

Archive/cache operational batch16 and64MiB segments can remain independent of128-payment blocks if iteration reaches every row. Body ordinal expands; output ordinal0/1 does not. Check full/scan/history LIMIT17 and schema header1232 limits, genesis source count, CLI count, head height<=leaf_count/2 and bounded integers. Full frame/stream exact EOF must reject appended bytes and incomplete final body; do not expose accepted state incrementally while reading a block.

A TCP archive acknowledgement is for a durably retained exact blob, not proof validity. It must bind the requested content identifier and size. After staged write/fsync/rename/directory fsync, lost ACK/restart/idempotent retry must verify the existing object's exact identity and retain/correctly account all temp and committed bytes; existence alone must not bypass integrity, durability or quotas. If archive validation is omitted by design, state that and still require receiving-ledger genuine validation. Receipt of a blob is not acceptance of its payments.

G1 RETAIN can legitimately complete destination retention without exporting its body cache. It does not establish annual decentralized node participation or erase the separate archive provision. Failure tests must distinguish a durable unaccepted archive blob from a partially accepted ledger block. Final genuine-invalid proof must reach the complete proof verifier on the ordinary admission path; rollback equality includes all actual schema tables and retention counters, with only explicitly diagnostic process counters excluded.
