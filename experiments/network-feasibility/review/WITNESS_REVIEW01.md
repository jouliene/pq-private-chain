## Why the current path construction works

Before incoming index i, the prefix forest contains exactly the completed subtrees corresponding to set bits of i. Each required left sibling for a newly discovered target is one such frontier subtree. Required right siblings are future aligned subtrees: a set of tokens waits on `(start,level)`, so multiple targets sharing a right subtree all receive its digest. `_subtree` captures both initial and merged subtrees. Live paths only capture complete real subtrees; incomplete future right subtrees remain unresolved there.

`view()` clones frontier/path/waiting state, pads the absent suffix with known empty subtrees and returns completed temporary paths. It does not put padded sibling digests into the live frontier; later real appends can therefore change the partial right subtree without contradicting an earlier view. Completed live sibling subtrees never change under append. `forget` removes both target state and its waiting references. Rewind restores a bounded snapshot, including forgotten targets and their paths; abandoned discoveries disappear. Revision checks prevent a pre-rewind epoch from publishing over the replacement branch.

This supports late discovery **when the corresponding leaf arrives**, not arbitrary retrospective insertion of an owned target whose leaf was already discarded. Real integration must discover inside ordered receipt processing before append, or explicitly replay common history/use the declared second-pass public spool. The public sparse/full-tree oracle occurs only in control/fixture harness code and is never passed into `stream.py`.

## Material bounded repairs before integration

1. `Epoch.apply` currently insists on nonempty leaves. Valid Network04 empty-only/interspersed/trailing blocks must instead preserve root/count, advance authenticated height/identity and recent anchors, and create bounded reversible journal state. Repeated root/count pairs remain eligible while present in the window; empty advancement cannot stand in for the required changing-root expiry control. This is a compatibility repair, not a reason to reject the selective frontier.
2. The memory formula needs a bounded live epoch lifecycle. The API currently permits arbitrarily many retained epochs and finished epoch objects retain state/history references. With one active epoch and prompt release, current state/view/snapshots are O((R+2)(D+KD+A)); old committed and tentative journals may coexist, changing the constant, not the asymptotic. With E independently retained epochs the bound must additionally account for E. Integration should enforce one active epoch, clear working references on finish/abort, and invalidate it on rewind. The author acknowledged both repairs and plans a new preserved SOURCE02 after canonical wallet-format work; neither is claimed fixed in SOURCE01.

K is the explicitly configured maximum live owned targets, R the private rewind depth, A the anchor ring and B the bounded block intake. Dictionary/set/tuple/object overhead, private note/opening storage, keys, and any retained caller witness objects are additional real memory; the algorithm counts are not an RSS upper bound. Peak block input and discovery callbacks must stay bounded. Overflow aborting an epoch is honest fail-closed behavior but means the participation model must choose a supported K; K=4 controls do not establish an unlimited wallet. Snapshot-sharing does not prove secure erasure. Private note lifetime/undo must retain data needed for allowed rewinds and wipe abandoned/expired last references without destroying surviving snapshots.

Anchor eligibility uses current selected-branch root/count and current unspent selected occurrence, not the transaction's claimed branch of origin. Deep rewind raises `ReplayRequired` and leaves committed state unchanged; actual authenticated reconstruction is still integration work. Header/leaf/source authenticity and endpoint validity belong to the fixed canonical adapter/declared validating source, not this callback-based diagnostic class. No public data-validity token or arbitrary producer-selected hash implementation may be minted from it.
