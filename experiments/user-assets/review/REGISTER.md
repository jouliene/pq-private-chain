# Non-author review protocol

The starting revision is `2bac7cc7e53fb4b5ddbe999d1e634224ba937900`. A new run uses a clean detached checkout, new build target, new local PoW homes, and fresh wallet keys for the issuers. Only deliberately disclosed numerical synthetic results and public network artifacts enter the review record.

* **Branch and money.** Check network, genesis, every block's PoW digest and ancestry, per-transaction anchor, each registered proof, the ordered ciphertext digest, two commitment/nullifier sets, fee, root, and the complete state commitment. Compute fork choice directly from the public graph. Recompute each reward commitment using independent code linked to pristine upstream primitives. Each selected height adds 100 native units. Exact gross miner credits equal issuance plus the native fees already debited. Each positive issuance cap is first registered by the selected branch and its immutable identifier matches the SHA-256 network and first-nullifier rule.
* **Private inventory.** Reconcile participant-disclosed directions, values, fees, change and selected history at the competing tips. The public proof verifies conservation and authentication but conceals each ordinary transfer's actual tag and allocation. Compare public commitments and nullifiers against wallet-recognized note rows privately during the clean run where available, reporting aggregate outcomes. A recovered balance is insufficient: check the restored owner's new A and B payments and both recipients' subsequent selected spends on their respective tested histories.
* **Fork boundary.** Require a fork that removes an issuer entry and payments of that asset; compare the losing branch, the common parent and the winning branch. Check the surviving asset's cap and origin; compare the node's selected nullifiers, commitment positions, receipt bytes, fees and registry with the full replay. A sampler outside the operator process records the cold peer's advertised height, work, tip and registry over loopback.
* **Relation and privacy.** Assess the real-slot membership / nullifier and typed-opening linkage. Check canonical tag zero on empty quantities, 62-bit bounds, integer conservation and the input requirements for issuance. Distinguish wallet-selection rejection, relation-level negative controls and selected-state rejection. Public metadata includes issuance ID, cap, first real nullifier, work, fees, packet sizes, timing and linkage across retries. The reference wallet puts its first real input in slot zero even on ordinary payments. Ciphertext digest binding does not prove a malicious sender encrypted the intended note to a usable recipient. Whole-system privacy, PQ knowledge and operation on a hostile network remain open.
* **Double change.** Use an actual qualifying payment with positive token change and positive native change, record the actual number of real inputs, two proved slots, two output commitments, proof and receipt bytes, native proving wall/CPU/peak RSS and verification wall/CPU/peak RSS under the measured run environment. Under single-asset-note semantics an external token payment and separate token/native changes need three nonzero outputs; an additional external native amount makes four. Record this counterfactual as an output lower bound under those rules, distinct from a benchmark of a single-asset prover.
