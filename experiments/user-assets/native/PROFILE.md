# AST1 tagged private payment relation

The registered direct blinded Qnero/Plonky2 relation accepts two input slots and two outputs under a single authenticated note tree. Each slot commits to a native amount and one asset quantity, both integers in [0, 2^62−1]. All positive quantities in one payment use one hidden transaction ID. The canonical on-note ID is that same ID when the quantity is positive, and zero when it is zero. The transaction ID is four little-endian 63-bit limbs. Its zero value occurs exactly for a transfer with no token outputs. The spend relation constrains each note's randomness as Poseidon2 with preimage [0x415354310001, ID0, ID1, ID2, ID3, quantity, raw0, raw1, raw2, raw3]. The existing two-layer note commitment binds pk, rho, this typed randomness and native value. Both input membership and the nullifier use that same opening. Dummy slots require zero amounts in both lanes and use a separate nullifier domain. Output rho derives from both ordered nullifiers and the output index.

Base public inputs 0–25 are the anchor hash, anchor height, two nullifiers, two commitments, native fee, and digest of the ordered ciphertext pair. Positions 26–29 are the four public issuance ID limbs, and position 30 is the public issuance quantity. The public limbs equal the private ID on issuance, and all five public words are zero on ordinary transfers. The circuit bounds supply to 62 bits. An issue requires positive supply, the first input real, and total incoming tokens zero. The exact integer equations are native_in = native_out + 3 and token_in + supply = token_out. Even the expression with two inputs and supply is at most 3(2^62−1), below the Goldilocks modulus. Native outputs plus fee also fit. Each independently issued ID has one fixed initial supply on the selected branch. This uses both proof verification and branch-state policy.

For issuance the wallet computes SHA-256 over the ASCII domain AST1/issue-id/v1 followed by one NUL, network identity (32 bytes) and the first real nullifier (32 bytes). Clear the top bit of each little-endian 64-bit word and reject the all-zero ID. The public verifier returns the approved proof effects. The node separately recomputes the ID from those effects and rejects an existing ID, spent or duplicate nullifiers, invalid anchors, and conflicting state updates. Ordinary transfers have no explicit asset identifier on the wire. Prior valid chain history ensures funded tags descend from authorized issuance. Public rewards commit no token value and use distinct AST1/reward/rho and AST1/reward/raw hash_bytes domains over the exact contextualized 80-byte reward body.

A canonical AST1 packet is ASCII AST1, width byte 1, u32 little-endian proof length, the complete proof and two ordered 1,792-byte suite-1 packets. Every receipt parser must validate the digest and canonical packet. Inside each encrypted plaintext the old two amount words carry native and token amounts. The other fields are rho32, raw32 and 61 memo bytes. Memo starts with the full ID32 and ends with a 29-byte wallet-local change marker (zero for an ordinary external output). Restore recomputes the typed note commitment and validates each decoded amount/tag. The marker is the first 29 bytes of Blake2b-512(domain AST1/devnet/change || spending seed || commitment). Ciphertexts are bound by their digest. The proof does not prove correct ciphertext generation or recipient deliverability by a malicious sender.

The profile keeps the TKN1 blinded direct configuration (Goldilocks D=2, 135/60 wires, 2 challenges, 5 rate bits, cap height 4, 26 queries, no grinding, constant (2,3) reduction). The single registered key is reconstructed by the validator from its approved circuit and compared byte-for-byte. It is independent of issuer and asset. Issuance publicly reveals ID, cap and first nullifier. Ordinary private token and native transfers share one profile, field count and packet length. Amount, ID and address privacy depend on qualified hiding, binding, multi-target hash and receipt-anonymity assumptions, plus the normal network and timing leakage. Public issuance timing, small holder sets, correlation with public rewards, and users disclosing asset data can identify a transfer by inference. The SHA-256 mask yields a 252-bit label space; generic ideal-hash collisions take roughly 126 classical or 84 quantum bits of work. Collision rejection protects the registry while a targeted existing ID is a preimage problem. Neither whole-system PQ knowledge nor multi-user joint privacy follows from the configured 128-bit proof parameter or finite tests.
