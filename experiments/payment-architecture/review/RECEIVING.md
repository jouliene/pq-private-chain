# Independent receiving-layer review

A concrete hedge worth a versioned experiment is MLKEM1024-P384. An offline exported public address holds both long-term encapsulation keys and the separate note spending identifier. The payer creates fresh encapsulation material for each output. The specified hybrid combiner derives **one common secret** for the existing encrypted note and memo. Giving each KEM a separately decryptable copy of the payload would expose the payload whenever either KEM fails. Use the specific combiner with its specified validation, serialization, labels, KDF and key binding. Specify the construction revision and known-answer vectors. These are design and byte estimates for a future suite. No hybrid proof, receiving latency or restoration result was measured. The table holds constant the 19-byte framing, 128-byte encrypted note, 16-byte memo tag and 61-byte padded memo. The address has a suite byte and a 32-byte spend identifier. The portable envelope adds 8+32+32 B. The 1024-preserving hedge costs 194 B per payment or 19.4 GB per 100M for each copy carrying both receipts. X-Wing changes the underlying FIPS 203 parameter set from ML-KEM-1024 to ML-KEM-768. Actual migration needs a new registered suite, receiver compatibility rules, canonical fixed lengths and field representation; the released verifier authorizes exactly 1792 B per receipt. The hedge protects recorded payload confidentiality against classical failures covered by the combiner's assumptions. Against a cryptographically relevant quantum computer, the EC component cannot carry the confidentiality claim on its own. A compromised wallet seed compromises both restored static secrets, including for previously recorded anonymous messages. Receiving-key backups need deterministic, independently labelled key derivations, algorithm versions and address indices. Retain old-suite trial decryption on seed restore and rollback. Public addresses can be shared offline. Repeated use already links the address presentations between their holders. Keep recipient key fingerprints, explicit receiver IDs and reusable KEM ephemeral keys out of public outputs. Public mining rewards in the current devnet explicitly identify the reward key and amount. [Hybrid KEM specification](https://datatracker.ietf.org/doc/draft-irtf-cfrg-concrete-hybrid-kems/04/) · [Existing reward disclosure](../../../devnet/CONSENSUS.md)

Recipient anonymity is a separate security game with competing known public keys and adaptive observations. In an ordinary concatenated encapsulation, an observer can inspect each component separately. If either permits distinguishing the recipient, the other component's confidentiality cannot hide that fact. This logic does not establish an efficient recipient test for either intact registered construction. The hybrid OKEM literature gives stronger obfuscation constructions and explicitly studies limitations of standard combiners. Its results do not supply a complete anonymity reduction for this note protocol, spending proofs, fee policy, timing or full-node queries. [Hybrid Obfuscated Key Exchange and KEMs](https://eprint.iacr.org/2025/408.pdf)

Bind a version, network, output position, the note commitment and applicable pre-encryption public context in the receiving KDF/AEAD as specified by the suite. Use fresh domain-separated key/nonce material for the note and memo. Have the payer authorize the final exact ordered ciphertext byte strings, including both encapsulations. Keep post-encryption transaction IDs out of pre-encryption context when their computation already depends on those bytes. On scan, authenticate before parsing the opening and recompute the note commitment against the authenticated selected-chain output. Check the independently authorized statement, including ciphertext digests, on public admission. An opaque digest proves what the payer authorized. A willing payer can still send unusable ciphertext for its own otherwise valid output. [HPKE context and AEAD](https://www.rfc-editor.org/rfc/rfc9180.html) · [Previous receipt-binding audit](../../advancing-payments/assurance/README.md)

Before selecting the hedge require two disconnected senders paying one exported address, two independent encapsulations per payment, seed-only discovery of both receipts, actual private spending, archival catch-up across a reorg, malformed component and cross-suite rejection, reordered/substituted receipt rejection, and measured full historical scan cost including trial decapsulation. Proving recipient anonymity needs a separate compound theorem and explicit adversary view.
