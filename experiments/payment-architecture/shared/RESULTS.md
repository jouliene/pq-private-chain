# Post-inclusion proof sharing

**Decision.** Allowing a producer to include a complete unilateral payment first and an independent archivist to aggregate it later removes batching latency from inclusion. A new three-slot APV2 certificate verified across transactions with different inclusion heights and anchors. A separate versioned block experiment replayed from genesis using only original preactivation bodies, two new PoW cores and this certificate. The present four-slot proof still costs at least **62,749.5 B per payment** at full packing, including receipts, before core or archive framing. Even ideal cross-block scheduling projects 6.285–6.316 decimal TB per archive-year at 100M inclusions. It also keeps the 230,206 B wallet packet and initial block delivery. Retain detached sharing as a candidate for a future cheaper proof system; it misses both 1/5 TB comparisons with the current registered widths. [Numerical results](evidence/COSTS.json)

## Original bytes and a necessary activation

PQDEV1 takes its PoW seed from the entire block template, including raw payment packet bytes. Its reward opening also hashes the raw packet vector. The aggregate verifies slot anchor digest and height, nullifiers, output commitments, fee and receipt digest, and returns both validated ciphertexts per slot. It does not prove the legacy singleton proof bytes or the packet hashes used by the old block. Supplying claimed historical template hashes to a new node cannot establish that the exhibited payment statements are what those templates contained. A PQDEV1 archive consequently needs its original raw bodies, or a different proof of their preimages and equivalence. [Published block and reward encoding](https://github.com/jouliene/pq-private-chain/blob/6502ebe7c01e174bcc8b9718130d7cb5f5dd8e63/devnet/chain.py) · [Registered APV2 decoder](../../advancing-payments/crypto/src/codec.rs)

The experimental fork explicitly activates after the legacy H3 prefix of the published author capture. Its network identifier binds the prior deployment, verifier profile, activation ancestor, height and new difficulty. Each 32-byte statement identifier (SID) is SHA3-256 over a fixed domain, network, original anchor digest, u32le anchor height, two nullifiers, two commitments, u64le fee and the SHA3-256 digest of the ordered 3,584 ciphertext bytes. Its fully serialized PoW core costs 222 B plus 32 B per payment. The core includes parent, height, miner, subsidy plus fees, reward commitment, state digest, funded root, slot count, ordered SIDs and nonce. The reward opening binds the ordered SID vector; the PoW preimage covers the whole core. The AP header binds to the selected core and state. A future wallet outbox would identify submitted transactions by SID and associate all authorized replacement SIDs with its local intent. Proof wire bytes can change without changing a core, reward opening or SID if all authorized public fields and receipts agree. [Exact encoding, transition and parser](replay.py)

For each new selected core, a full node needs a verified certificate covering **every** referenced SID. An ordinary singleton is sufficient immediately, including while the archiver is offline. A registered wrapper is another source of authenticated slot data. A fresh verifier checks the whole supplied proof and both ciphertexts for every slot. Replay resolves only the slots named in each core and then checks inclusion at that original height, its actual branch anchor, the current spent set, commitment uniqueness, fee, issuance, reward commitment, funded root and state digest. A proof cannot authorize a late block merely because the payment was valid somewhere in the past. All unreferenced wrapper slots are inert. This permits a reorg to reuse an existing certificate for surviving statements and a different certificate or singleton for newly selected ones.

## Fill, service and traffic

The author PoW capture included three payments over fifteen selected blocks, with thirteen empty blocks. The first paying block preceded the second by 30.495 s. Adding measured warm proof time to the actual mined inclusion times gives a 49.229 s temporary retention interval for the oldest singleton. There is no extra consensus waiting step. On the separately measured twelve-payment trace with ten-second offers and 48 empty two-second opportunities, one warm four-way archiver would have held up to five complete singletons simultaneously, for up to 47.233 s each. This scheduling replay estimates retention from existing real timestamps and measured proof service. It did not run those miners simultaneously with a detached builder; sharing a CPU with block production or direct verification could slow either. Closing a sparse pack early uses a registered smaller width, and a final lone payment keeps its original singleton indefinitely. The original H3/H4 paid pattern projected into the alternate format uses 694,132 B direct versus 250,712 B with one three-way certificate. Ten archived alternate blocks with another payment need a separate 232,518 B if kept directly. ## Availability, forks and scope

The root of trust remains full replay from genesis with source-pinned verifier data and the public receipts. Before activation the loader needs all original selected bodies. After activation it needs each selected core, every associated statement's complete valid proof source and recoverable receipt bytes. The experimental decoder uses a single local in-memory archive, including a SID dictionary assembled from authenticated evidence. It accepts extra valid evidence. Production peer ingestion needs streaming, limits on unrequested certificates and duplicate bytes, incremental lookup and durable sidecar references. Different honest peers can retain different certificate packs for the same selected work. A branch-aware sync exchange could request missing core ranges by ancestry, resolve missing SIDs from any complete source, and fall back to singleton retrieval. Refusal or withholding can delay synchronization even where work headers are widely available. The current operator's original transaction-hash wallet, reward derivations and PoW block IDs require explicit migration.

PoW has no fixed archival finality. When a branch loses, remove only its selected state effects and retain enough evidence to replay any side branches covered by local archive policy. A certificate addressing an orphan can still supply intersecting valid statements if rechecked on their new branch. Never treat its other slots as spent or eligible on that branch. The fixture holds alternate cores and the same certificate in memory and recomputes both states. A genuinely conflicting spend needs separate evidence, and every separately retained branch adds its cores and any otherwise absent sources. A detailed operator can prune after independently verified parity and a recoverable installation of the replacement, but a node that discards both source packet and detached certificate becomes unable to serve or verify historical state. The original author capture's selected and side-copy counts supply one measured branch shape, not a bound on indefinite fork retention.

APV2's inherited circuit/Fiat–Shamir, PQ knowledge/soundness and privacy assumptions remain. Binding also relies on the new domain-separated statement/hash, ordered core, ciphertext and reward commitments. Offline aggregation groups already public slots, exposes packaging and can correlate traffic or timing. There is no trusted coordinator or privileged finalizer. Exact equivalence here concerns named public slots and receipt bytes. The encoding offers no simultaneous assurance about malicious availability, network anonymity, chain-level PQ security or private assets. The proposed detached container and new network have no independent production security proof. [APV2 assurance](../../advancing-payments/assurance/README.md)

## Reproduction

From the repository root, prepare the public devnet runtime using the documented pinned build. Set `run` to that runtime directory and `scratch` to a new disposable path. Verification, the fixture and the scheduler need no wallet keys. The builder path performs one optional fresh expensive proof and requires unused output storage. Fresh hiding randomization changes its certificate identity.

```sh
python3 -IB experiments/payment-architecture/shared/replay.py --runtime "$run" --certificate experiments/payment-architecture/shared/evidence/certificate.bin
python3 -IB experiments/payment-architecture/shared/costs.py
python3 -IB experiments/payment-architecture/shared/build.py --runtime "$run" --out "$scratch/new-proof"
python3 -IB experiments/payment-architecture/shared/replay.py --runtime "$run" --certificate "$scratch/new-proof/certificate.bin"
```

For archive bytes on disk, pass `--out "$scratch/archive"` to the replay command. The proof/receipt packet is public and the receipt opening keys never enter these scripts. [Runtime build and receipt checks](../../../devnet/crypto/README.md)
