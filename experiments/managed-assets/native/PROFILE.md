# MNG1 supply relation and issuer primitive

The registered MNG1 proof has two input slots, two outputs, and 31 public Goldilocks elements. It uses the same typed notes, native rewards, real/dummy nullifier separation, encrypted payloads, fee of three native units, 62-bit value lanes, and blinded proof parameters as [AST1](../../user-assets/native/PROFILE.md). The inner packet changes its first four bytes to MNG1. It retains width one, u32-LE proof length, proof bytes and two ordered 1,792-byte ciphertexts. Every note with positive token quantity contains the same transaction asset ID, a nonzero four-limb digest with each limb below 2^63. A note with zero token quantity always contains zero ID. The public-only verifier checks proof, canonical encoding and the digest of the accompanying ciphertexts, then returns the same structured effects as the AST1 verifier.

Positions 26–29 disclose the ID for a supply operation. Position 30 is a canonical 63-bit encoded word. Zero means ordinary transfer and requires all four public ID limbs zero. An unflagged positive word is a mint. A word with bit 62 set is a burn. The bottom 62 bits encode its positive magnitude. A set bit 63 or a flagged zero magnitude is invalid. A mint constrains all incoming token quantities to zero and requires input zero to be a real funded note. The circuit compares token inputs + mint with token outputs + burn. These nonnegative integer sums are each at most 3(2^62−1), below the field modulus. Both sides include only tokens under the common ID; dummy inputs are constrained to zero in both lanes. The hidden ID is nonzero exactly when token inputs + mint is positive, including full liquidation. The note commitment and Merkle membership constraints require the holder's spending credentials to consume a real note. A public issuer signature alone cannot burn another holder's note. A burn needs native fee funds under the inherited native conservation equation.

Proof verification returns raw public deltas; the outer consensus policy determines fixed registration, managed registration, further mint and permitted burn, verifies governance authorization, checks operation ordering and limits, and applies the inventory change atomically. An unflagged positive inner delta alone conveys no authorization to increase an existing asset's supply. The private wallet uses AST1 scan/open, receipt and funding-path codecs. The K frame takes the encoded delta in the previous supply slot. A standard burn uses zero requested recipient amounts, a self destination and an encoded burn. Change holds the surviving token units and native after fee. There are always two commitments and two receipts, even when one or both have zero economic value.

## Issuer signing

The wallet derives the 32-byte MNG1 issuer seed as SHA-256(ASCII MNG1/issuer-seed/v1 || NUL || wallet_seed32). Qnero's SlhDsaSecretKey::generate_deterministic expands this seed through the pinned SHA-256 counter generator for RustCrypto's SLH-DSA-SHAKE-128f key generation. Wallet command J returns the 32-byte public key. Wallet command L takes exactly the protocol's 32-byte outer message digest and returns a 17,088-byte deterministic pure SLH-DSA signature with empty FIPS context. Public verifier command V takes public key32, message digest32 and signature17088 in that order. It returns ASCII 1 for acceptance or 0 for rejection. Each is one ordinary length-delimited IPC request. The protocol's separate outer-domain digest covers the operation, network, relevant state and inner packet. The issuer key signs only those protocol digests. Holder burn authorization lives inside the spend proof. Deriving an issuer key from a backup means its compromise exposes both spending and issuer authority until the branch records any supported authority change.

Qnero f04c91307837c0231668383bec76ba98d89d2652 uses qnero-pqcrypto 0.1.0, sha2 0.10.9 and RustCrypto slh-dsa 0.2.0-rc.5. This is a release-candidate library and application-specific seed derivation. The functional tests below exercise signature parsing, repeatability and tamper rejection. A standardized underlying algorithm does not validate the implementation, prove joint wallet privacy, or certify the full protocol. ## Reproduction

Use the same pristine Qnero checkout and Rust 1.93.0 as AST1. Build into a new output directory, using a fresh target for clean reproduction. The role reads no private input to register or verify. The relation test creates ephemeral wallets internally, including an independent holder for the wrong-ownership test. It submits each witness to the full prover and checks any returned proof with the registered verifier. The JSON boolean in each case is the verdict, so negative controls are false.

```sh
python3 -IB experiments/managed-assets/native/build.py "$lab/build" "$upstream" "$lab/target"
RAYON_NUM_THREADS=2 "$lab/build/native" register "$lab/build/registered"
cmp "$lab/build/registered/managed.vk" experiments/managed-assets/native/registry/managed.vk
RAYON_NUM_THREADS=2 "$lab/build/native" check-relation "$lab/build/registered" | cmp - experiments/managed-assets/native/CHECK.json
```
