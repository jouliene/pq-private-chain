# Independent funded-membership assurance review

Baseline `415280581a07d3d246a5408ad32b7e3e922041e7`. The question is whether a newly admitted debit must consume a previously funded, spend-authorized positive note exactly once. The released positive A/B payments and independent public replays establish that particular legitimate debits work. The implication for every accepted debit requires both a knowledge or direct-authorization argument for the proof and a binding argument for its exact relation.

## What an extracted witness establishes

The funded MNG1/SLG1 profiles and their MNG2/SLG2 successors use the same note, nullifier and tree semantics. The B build changes FRI registration. The node binds the proof's anchor and height to a recent ancestor on the selected branch, checks the current spent set and reconstructs the next state. An extracted real-input witness would bind its ownership key, value, typed note opening and nullifier and would supply a path to the root inside a matching header preimage. Dummy quantities are zero. The node separately checks fees, issuance policy and the joint swap. The inference from this path to an actual funded note is the unresolved step. [Baseline registrations](../../funded-upgrade/PROFILE.json) · [Pinned relation](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/circuit.rs)

The branch's successive four-way groups use sorted little-endian digest encodings, a count-derived depth and zero padding. The verifier lets both inputs share a private depth in 0…20 and constrains each active level to hash the running digest and three supplied siblings. The public statement lacks a constraint equating that depth to the branch's depth or mapping the sorted child slots to an occupied insertion index. Sorting discards the original sibling order. A sorted slot and an occurrence index have different meanings. The underlying parent input has four digest children and lacks an explicit level or parent tag. Leaves, padding and internal digests occupy the same four-word output space. [Pinned tree and circuit gadgets](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/merkle.rs) · [Historical source audit](../../new-note/baseline/LIVE.md)

The missing premise is the infeasibility of producing a satisfying, positively valued, authorized opening under an eligible branch root that differs from every legitimate funded opening at that anchor. The binding argument must cover alternate header preimages, unequal path shapes, encounters with internal or empty values, and ambiguous note or ownership openings. For single consumption it must also ensure that the same funded value cannot acquire a second accepted nullifier through another opening or verifier route. Two legitimate notes accidentally sharing a nullifier instead raise an availability risk. Nothing in the observed mismatch alone establishes an unauthorized debit, restored supply, or a concrete cost for taking someone else's funds.

### Prospective C rule at H25

C keeps the same sorted tree, leaf commitment, authority, true nullifier and receipt. The new 32nd MNG3 / 35th SLG3 public word is the exact depth target used for the circuit's active-level flags. At admission the node must look up the count at the selected, eligible transaction **anchor**, derive the depth, and compare the verified public word to that depth. A cached head count or producer-supplied count would sever that binding near a depth change. The new common constraints require a nonzero running child at each active hop for a real slot and a nonzero final root. The wrapper also excludes zero public depth. Real spending at the empty genesis root is thereby excluded. The added word reveals the depth of the already public eligible anchor. Verifier replies carry its checked one-byte representation. [Circuit change](../hardening.patch) · [Bindings in both registrations](../build_c.py)

For an extracted positive real input, condition first on the header digest binding the witness to the correct branch root. Traverse the witness path **from that root down**. At each of exactly d levels the honest parent has a particular sorted tuple of four canonical children. Equal parent outputs imply equal ordered tuples unless parent binding fails. The selected child coincides with a child in that tuple, and its nonzero check excludes every unoccupied padding slot. Inductively the final child is an occupied leaf at the funded level. Equal child digests or differing insertion positions do not invalidate this existence statement. Chronological position is unavailable after sorting. At the leaf, binding of the typed note and its ownership opening is still required to attribute an authorized value and derive the historical nullifier.

The zero rule is a one-way soundness condition. The existing frontier rejects a zero funded leaf, but its parent combiner accepts any canonical result, including zero. A genuine occupied subtree or entire funded root that hashes to zero can therefore make the corresponding true opening unspendable under C. The observed finite funding histories can be checked directly. Universal liveness needs a bound on that event or a distinct versioned representation of occupancy. [Original frontier](../../advancing-payments/state.py)

H25 retirement must cover every path that consumes inputs, including fixed issuance, registration, mint, burn, native transfers and both legs of an indivisible swap. Verify old blocks under the rules at their actual heights and pending packets under the next candidate height. On a reorganization, roll back and reapply supply, fees, real and padding nullifiers, receipts and anchor metadata together. Cross-era retries must retain the same real lifetime identity. All prospective routes must be hardened for a C-only claim. The provenance and authorization assumptions of previously settled supply remain those of its historical rules.

N7P2 demonstrates explicit chronological membership and a separately funded one- or two-input path. Its 49 public values, registered gate, verifier and ledger checks are necessary for that result. A second ordered index over original commitments would add different semantics and storage obligations. With either index the old commitment still determines which private value may be spent. ## Quantitative quantum claim

Let `p = 2^64 − 2^32 + 1`. Four canonical Goldilocks words occupy slightly less than 256 bits. For an ideal uniformly random 256-bit function, generic constant-success single-target search takes order 2^128 quantum evaluations. A search with T usable independent targets takes order 2^128/√T under efficient coherent target recognition. An unconstrained ideal collision has an order-2^85.3 query benchmark with substantial memory. A collision must satisfy additional note, ownership, funding and branch conditions to have a monetary effect. These figures are illustrative query counts, with distinct games and resource models. [Boyer et al., multiple-solution quantum search](https://arxiv.org/abs/quant-ph/9605034) · [Brassard et al., quantum collision algorithms](https://arxiv.org/abs/quant-ph/9705002)

For example, T = 2^20 suitable independent targets gives an ideal four-word search scale of approximately 2^118 queries. An attacker who can choose both origins of a collision faces a different task from opening a recipient-selected paid note. A valid monetary advantage must be demonstrated or reduced to the corresponding game. At most eight ancestor heights are simultaneously eligible under the funded ledger. A recent root can still cover many old unspent notes, so eight is not a bound on the number of eligible note targets.

As an example under the prior researcher workload, 100M included operations/year, 90% transfers and 10% two-leg swaps give 4.4 billion ordinary/swap output occurrences over 20 years before rewards. If all were independent usable targets, ideal four-word search would have a log₂ query scale of about 112.0. Reused owner keys, spent notes, public burns or locked supply, a short anchor window and the ability to choose funded outputs affect which targets qualify. For a sequence of R attempts with a per-attempt bound ε conditioned on the prior transcript, the union bound gives at most min(1, Rε) for any success. An estimate proved only for one fixed transcript supplies no such adaptive bound. A proof obligation against arbitrary collisions would have different parameters. The 256-bit legacy wallet seed likewise caps the nominal single-seed generic search scale. Neither workload nor nominal primitive width establishes protocol security at a stated success probability. [Prior workload and wallet assumptions](../../advancing-note/DECISION.md)

The seven-word N7P2 digest and capacity (roughly 448 bits) give different ideal benchmarks, approximately 224 query bits for one target and 149.3 for arbitrary collisions. Its width-12 Goldilocks permutation, rate-five absorption, domain and length injection and two-step squeeze require concrete cryptanalysis or a reduction applicable to these exact parameters. Likewise the two-challenge PLONK/FRI profiles need an analysis covering the actual field, code rate, folding, list/proximity hypotheses, oracle openings and blinding. To claim 128-bit quantum spend knowledge, state the failure probability and query/time/memory budget for the interactive relation, commitment binding, Fiat–Shamir transformation and adaptive many-proof setting. A library security setting, a number of FRI queries and the availability of a generic QROM Fiat–Shamir theorem leave these inputs unspecified. [N7P2 sponge](../../advancing-note/proof/src/sponge.rs) · [Poseidon2](https://eprint.iacr.org/2023/323) · [Reed–Solomon proximity gaps](https://eprint.iacr.org/2020/654) · [Multi-round QROM Fiat–Shamir](https://eprint.iacr.org/2020/282)

## Receiver and joint observation

The funded software uses ML-KEM-1024 and separately labelled ChaCha20-Poly1305 payloads for the note and memo. The proof's public receipt digest binds the ordered envelopes. A receiver must decapsulate with its own key, check the expected spending key, rebuild the typed opening and match the selected funded commitment. N7P2 uses a different SHAKE-based KDF and AES-256-GCM envelope. Legacy seed restoration must still decode legacy envelopes and derive the corresponding spending authority. [Funded receipt construction](../../spend-proof-decision/RECEIVING.md) · [N7P2 wallet](../../advancing-note/lab/wallet.py) · [FIPS 203](https://csrc.nist.gov/pubs/fips/203/final)

The privacy game needs two equal-public-metadata worlds, challenge restrictions on corrupt participants, multiple receiving keys, adaptively chosen payments and observed later spends. It must account for aliases between proof openings, ciphertexts, public commitments, nullifiers and swap approvals. A malicious payer knows its beneficiary and can send an unusable envelope. A holder of a compromised historical receiving seed can trial-decrypt archived ciphertexts. Fixed swap slots, retry nullifiers, fork events, visible amounts of public mint/burn and network timing constrain the anonymity claim. Correct decryption, indistinguishable same-cursor range requests and the FIPS KEM security target are distinct evidence for the system. Establishing the combined claim requires a multi-user key-anonymity/robustness argument for each envelope and a simulator or reduction for the whole adaptive joint view. [Bellare et al., key privacy](https://doi.org/10.1007/3-540-45682-1_33) · [Abdalla et al., robust encryption](https://iacr.org/archive/tcc2010/59780477/59780477.pdf)
