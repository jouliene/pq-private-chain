## A/B derivation and its missing premise

The historical verifier proves root equality at a prover-selected depth in 0…20. Assume extraction, correct header binding, unique typed openings and binding of the parent hash for honest/adversarially supplied child tuples. At equal depth descending the authenticated tree ties the path to an occupied commitment unless it can use zero padding. At **shorter** depth the witness can end at a digest with an internal-node interpretation. A monetary argument must rule out finding an authorized positive note that opens to that digest. At **greater** depth the witness can interpret a funded leaf as a parent or continue through padding. This requires a binding argument across typed leaf and parent encodings and resistance to suitable zero preimages. Sorting within a quartet removes the physical order even for a perfect hash. Funds require an occurrence, not an exact chronological position. The historical tests establish legitimate authorizations and branch effects. No unauthorized spend is demonstrated. [Historical source mapping](../new-note/baseline/LIVE.md) · [Independent argument](review/ASSURANCE.md)

C fixes the shape used for actual admission. If the extracted path has an occupied parent, equality to an honest funded parent forces equality of its four ordered child digests unless there is a binding failure. Nonzero excludes every missing child. Descend exactly the authenticated depth and the result is an occupied leaf; note and authority binding then yield the real spend identity. An exceptionally zero digest at an occupied internal node can deny spending through that path. The full-tree checker explicitly tests the measured histories for this condition. The historical supply and ownership assigned before activation still rely on A/B. A new verifier cannot reverse undetected historical inflation.

## Launch boundary

Targeting 128-bit security against adaptive quantum spenders requires an end-to-end knowledge or direct monetary-soundness bound for the exact Goldilocks PLONK/FRI transcript, the four-word hash games actually used for funding, and lifetime multi-target losses. The flags for row and leaf hiding establish configuration facts. They provide no simulator for the combined proof, signatures, retries, receipts and later spends. The public depth is fixed by a public ancestor. Receipt confidentiality uses ML-KEM-1024 plus authenticated symmetric encryption. A KEM standard alone does not establish recipient anonymity or the joint simulation. The independent review gives conditional query estimates and separates chosen collisions from the cost of spending someone else's note. [Independent security analysis](review/ASSURANCE.md) · [Non-interactive FRI analysis](https://eprint.iacr.org/2024/1161) · [Multi-round quantum Fiat–Shamir](https://arxiv.org/abs/2003.05207) · [FIPS 203](https://csrc.nist.gov/pubs/fips/203/final)

The next launch decision turns on a concrete adaptive, multi-user binding/knowledge argument for positively valued funded spends at the deployed parameters. Price wider, domain-separated note and tree digests plus atomic legacy consumption if the four-word profile cannot meet the agreed security game. This release upgrades full validating peers with original block bodies. A full database with unmarked post-H24 history must replay original blocks under C in a fresh store. The earlier sealed pruned-store implementation has a different checksum schema. In-place conversion of an already pruned database has no acceptance evidence here.
