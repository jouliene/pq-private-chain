# N7P1 private spend relation

N7P1 spends two funded notes of one owner and creates two notes with independent owners in a fresh 40-level binary tree. A note can carry native currency and one private fungible asset. The arithmetic relation covers hidden ownership, membership, nullification, conservation and output creation. The accompanying ledger handles authorized funding, branch anchors, accepted leaf counts, current spentness, receipt availability, fee policy and both swap signatures. An ordinary recipient with only one positive note still needs a second positive same-owner input in this fixed-arity experiment.

## Field and note encoding

The field is Goldilocks, with prime `p = 2^64 - 2^32 + 1`. A digest contains seven canonical field words. Its byte encoding concatenates their 8-byte little-endian representations. Any input word at least p fails parsing. The wallet's 160-byte receipt plaintext encodes owner (56 bytes), asset (32), salt (56), native (8) and token (8). The following field order is used for hashing, independently of the plaintext layout. There is no modular reduction of arbitrary asset bytes or receipt-context bytes. Each four bytes becomes a little-endian u32.

The base permutation P is qp-poseidon-core 3.1.0's 12-word Poseidon2 with 8 full rounds, 22 partial rounds and degree-seven S-box. Cargo.lock pins the distributed constants, whose upstream seed is 0x3141592653589793. N7P1 uses its own additive sponge. To calculate H(tag, w), initialize twelve words to zero, put 0x4e375031, tag and the number of input words in lanes 5, 6 and 7. Add each successive block of up to five words into lanes starting at zero, then apply P. For an empty string apply P once. Return lanes 0 through 4 of this final state followed by lanes 0 and 1 after one additional application of P. All identifiers below have fixed arity. The hidden note opening and owner identifier stay in the proved witness.

| Object | Tag | Input field words |
| --- | ---: | --- |
| Owner | 1 | Seven secret spend words |
| Note commitment | 2 | Owner[7], asset[8], native, token, salt[7] |
| Nullifier | 3 | Spend words[7], absolute leaf index, note commitment[7] |
| Empty leaf | 4 | Empty |
| Public statement | 5 | Root[7], count, fee, context[12], ordered nullifiers[14], ordered commitments[14] |
| Parent at level k | 256 + k | Left digest[7], right digest[7] |

The least significant position bit selects the first branch from a leaf at level zero. Each parent costs four permutations. Two independent depth-40 paths cost 320 permutation calls before shared subexpressions. The wallet's uncompressed sibling material is 4,480 bytes. The proof publishes neither path. A fresh salt blinds an ordinary output even when the payer knows the recipient descriptor. A payer knows its own outputs and can retain their openings. Public funding grants intentionally expose their owners and issued balances.

## Constraints and verifier identity

Both inputs use the same seven-word secret. Their owner identifiers, input commitments, nullifiers, oriented paths and common root follow the table. Each input must have positive combined value. Their 40-bit indices differ. The field values `count - 2`, `2^40 - count` and `count - 1 - index` must each fit 40 bits. Together these constraints allow a full tree, require at least two positions, and enforce an actual funded position below the count accepted by the ledger. On a selected branch, each accepted occurrence is identified by its absolute position and commitment. An independently funded second occurrence of the same commitment at another index has a different nullifier input. Distinct outputs and computational unlinkability depend on the keyed-hash assumption. Changing the mode, descendant anchor, recipient or proof for the same funded position and commitment preserves its nullifier. If a reorganization removes an occurrence and the record is re-included at another index, its nullifier input also changes. Restore must discard the orphaned path, spentness and occurrence mappings, then derive the new path and nullifier from the selected history. An old proof relies on its original authorized branch anchor. Shared public receipt or commitment bytes can still link the two inclusions. A ledger granting two occurrences must account for both credits and reject unauthorized replay.

Each note has native and token amounts in [0, 2^62). The asset ID equals zero exactly when its token balance equals zero. For every pair of notes with positive token amounts all eight ID limbs agree. The circuit equates input native value to output native value plus fee, and equates the token totals. Both sides of each equality fit below p. The circuit enforces `fee * (fee - 3) = 0`. Ordinary admission charges three. Two swap legs must agree which one pays the single fee. Outputs may have zero value. A node checks distinct unspent nullifiers in its selected branch and applies both outputs and the fee atomically. The full network, genesis and receipt-context framing are implemented in the integration area. [Ledger and wallet](../lab)

For each transaction, the public verifier rebuilds the same fixed Rust constraint program from a canonical statement. It compiles the seven words of the expected H(5, statement) into constant gates. The witness computes H(5, effects) from its constrained root, count, fee, a context of twelve checked u32s, derived nullifiers and derived outputs. All seven digest words must match. Separately, the complete statement words enter the circuit domain separator, which is hashed into the SHA3-384 circuit identity. The core backend public-input vector is empty. Its mandatory four-word hash is a fixed zero constant. Receiver, root, key, fee, swap mode and receipt changes must be reflected in the canonical statement or its context before the caller invokes verification. No producer key, verification program, witness or cached verdict is accepted on this interface.

qp-plonky2 1.5.5 compiles a quartic Goldilocks extension, blinded rows for wire and permutation-Z polynomials, salt on the secret-bearing FRI leaves and the parameters in REGISTER.md. The transcript observes the specialized circuit digest, empty public-input hash and wire commitment cap, then samples the permutation challenges. The Z/partial-product cap precedes alpha, the quotient cap precedes the quartic opening point, and the openings precede FRI's mixing challenge. Each fold cap precedes its fold challenge, with the final polynomial and proof-of-work phase before the 32 query indices. The code pins the proof commitment hashes and 16-lane challenge transition in oracle.rs. Proof compression elides shared Merkle siblings, duplicate openings and locally inferable quartic evaluations. Verification reconstructs the expanded proof, requires its recompression to match every transmitted byte, and verifies its full shape and equations. Wire input is bounded at one MiB. The parser takes tree heights, number of queries, coefficient lengths and caps from the local relation, uses one byte per explicit sibling count, and bounds every transmitted query index. A malformed compact path can trigger a caught upstream panic in the disposable verifier process.

## Reproduction and measurements

With Rust 1.93.0 and the lockfile's packages available, run from the repository root.

```sh
export CARGO_TARGET_DIR="$PWD/.work/n7p1-target"
export RAYON_NUM_THREADS=4
cargo +1.93.0 build --locked --release --manifest-path experiments/new-note/candidate/Cargo.toml
python3 experiments/new-note/candidate/check.py "$CARGO_TARGET_DIR/release/n7p1" .work/n7p1-new-check
python3 experiments/new-note/candidate/size.py .work/n7p1-new-check/proof.bin
```

The CLI accepts `eval` with a single JSON operation, `eval-batch` with an array or `eval-stream` with one operation per line. Operations are owner(sk), note(note), nf(sk,index,commitment), empty() and parent(level,left,right). Each returns seven canonical integers. Example public request: `{"op":"empty"}`. The modes `prove STATEMENT.json PROOF.bin` and `verify STATEMENT.json PROOF.bin` return JSON meters and a process exit status. Only the prover reads its witness from standard input. Statement keys are root, count, fee, context, nullifiers and outputs. The witness has two inputs with note, sk, index and path and two output notes. A note has owner, asset, native, token and salt. A path lists 40 siblings in ascending level order. Unknown fields, malformed dimensions and out-of-range external scalars fail closed.

The relation-only run used a Core i7-8700K with four Rayon threads. The fresh public process recreated the specialized constants and verification data from the statement. The measured compressed proof was 226,239 bytes, expanded to 267,504 bytes. Proving plus internal verification took 5.48 s wall and 1,855,456 KiB peak RSS. Fresh verification took approximately 1.9 s wall and 728,884 KiB, including 1.775 s circuit preparation and 12.37 ms for decoding, expansion, canonical recompression and proof checking. There were 664 gates before blinding and 16,384 rows in the final trace. Earlier expanded-wire checks rejected six public-statement mutations and seven inconsistent witnesses. The integration results separately measure actual payment, exchange, receipts, storage and recovery. [Measured runs](MEASUREMENTS.json)

The codec has a 14,368-byte prefix, 32 four-byte indices and a 136-byte footer. Each distinct initial query needs 243 field words and four sibling-count bytes across four oracle trees. A distinct query at each of the six folds needs three quartic elements and one sibling-count byte. Additional Merkle nodes are 48 bytes each. With a(d) occupied prefixes of depth d, a tree of height h needs the sum of `2*a(d-1) - a(d)` siblings for depths 5 through h. Four initial trees have height 19. The six folded trees have heights 17, 15, 13, 11, 9 and 7. Maximizing occupied prefixes at every depth, achieved when the 32 upper five-bit prefixes are distinct, gives **246,120 bytes**. Under 32 independent uniform queries the expected size is **232,113.59 bytes**. The estimate describes index sampling and excludes signatures and receipts. Consequently even a successful fit for a sampled signed leg leaves a larger permitted proof shape. [Executable size model](size.py)

## Security boundary and comparison

The seven-word output has `7*log2(p)` bits of possible range, close to 448. Generic birthday work for a random function of this size is roughly 2^224. Idealized quantum collision-search query scale is roughly 2^149.3, compared to roughly 2^85.3 for four words. This removes the narrow digest range from note commitments, tree roots and nullifiers. It supplies no lower bound for this concrete permutation, sponge or a fraudulent spend. Full-state algebraic attacks may dominate. SHA3-384 offers a standardized independent baseline for the alternate note. Its idealized quantum collision exponent is 128. Both constructions still require a suitable hiding proof and independently authenticated state. [Poseidon2](https://eprint.iacr.org/2023/323) · [Generic quantum collision search](https://arxiv.org/abs/quant-ph/9705002) · [FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)

Published ideal-permutation sponge results address bit-string sponges and post-quantum oracle models. N7P1 uses field addition, tagged capacity initialization, exact field lengths and cross-block squeezing. A concrete reduction for this encoding, for keyed nullifiers under adaptive chosen notes, and for the actual width-12 permutation remains open. The wide output count alone supplies no PRF assumption. The integration wallet uses a 48-byte seed with separated derivations. Even ideal exhaustive multi-target key search depends on seed entropy and the number of exposed targets. A backup compromise can expose historical receipt information and permit subsequent spends. The recipient must decrypt and recompute the funded output commitment. A malicious payer can withhold a usable receipt or disclose its payment. [Alagic et al.](https://arxiv.org/abs/2504.16887)

The outer Merkle hash is SHA3-384. SHAKE256 processes all sixteen challenge-state words and rejection-samples canonical field words. This is a deterministic public transition with no premise establishing it to be a random permutation. Quartic challenges expand the field used for algebraic openings. The 32 selected queries give a conditional factor of (1/4)^32 at hypothetical one-quarter agreement under independent uniform sampling, before list sizes, Fiat–Shamir losses, adversarial choices or knowledge extraction. No proof establishes 128 bits of quantum spend knowledge, adaptive multi-user zero knowledge, or joint privacy for the wire proof, identifiers and receipts. A concrete simulation of every opening and an extractor or direct unforgeability argument remain necessary. A universal replacement decision would additionally need a reproducible faster public preprocessing path and a maximum signed-frame analysis for the chosen registration. [Reed–Solomon proximity gaps](https://eprint.iacr.org/2020/654) · [Quantum multi-round Fiat–Shamir](https://eprint.iacr.org/2020/282)
