# SHA3-384 reference for new funded notes

**Reject the N3R1 + N3B1 pairing for a funded pilot.** The counted 2-in/2-out proof is 542,316,880 bytes. One signed leg exceeds the 262,144-byte research frame by 542,075,678 bytes. An honest branch cannot include this encoding with the current frame. N3R1 is a reference *new* note family with a standardized digest; N3B1 is one priced proof system. This result leaves room for a different Keccak proving system. The clear evaluator, Keccak component and receipt tests ran, without generating a complete proof or admitting new notes.

## Exact note and branch relation

Integers use unsigned little-endian fixed widths. Byte strings have fixed widths unless specified. Define H(t,...) as SHA3-384(ASCII N3R1 || u8(t) || concatenated fields). Network is the common public 48-byte network identity. New registrations, wallets, anchor/state tables, packet magic and address descriptor are distinct from deployed MNG1/SLG1. The verifier registers this relation and codec by consensus. A spender cannot choose an alternative circuit. [FIPS 202](https://csrc.nist.gov/pubs/fips/202/final)

- Let s be a 48-byte spend secret, and A = H(1,network,s). A note plaintext is A[48] || asset[32] || fresh salt[48] || native:u64 || token:u64. Its commitment C = H(2,network,plaintext). At least one amount is positive. A zero token amount requires a zero asset ID; a positive token amount requires the common nonzero asset ID. For this fixed ordinary role both input slots and both output slots are real. Native-only notes carry the zero asset. Input secrets and amount arithmetic never enter the public statement.
- A spend/leg output's occurrence O = H(8,network,kind:u8,sortedNF0,sortedNF1,slot:u8). Sort the pair as unsigned lexicographic byte strings. Kind is 0 for transfer, 1 or 2 for the swap side. Slot is 0 or 1. The same unordered NF pair cannot fund two admitted transactions on a branch. For separately authorized funding, O = H(9,network,uniqueCreditID[48],slot:u8). Ledger rejects reused credit IDs, duplicate occurrence IDs, duplicate NFs anywhere in the operation and already-spent NFs. Repeated commitments with separately authorized funding have independent value and remain spendable. For exact admitted history replay the identifiers survive index, root, confirmation height and signature/proof changes. The depth-40 tree is branch-local, ordered by admitted transaction, leg and slot. Its empty leaf is H(4); a real leaf is H(5,O,C). Parent at level l = H(3,u8(l),left[48],right[48]), l=0..39. Empty subtrees use the same parent function. Root R = H(6,network,count:u64,top[48]); reject count outside 1..2^40 for spending. The ledger authenticates eligible (count,R) on this branch.
- Per input the circuit derives C from the shared spend authority, amount openings and common asset; derives leaf(O,C); proves the 40-bit private index is below the public count; swaps the current value and private sibling for each little-endian index bit; checks R; and enforces public NF = H(7,network,s,O,C). NF uses neither index nor anchor. The same occurrence under a moved index/updated anchor gives the same NF. A copied note with a different funded O has a different NF. A mutation to just O invalidates both the leaf and NF. Retain the spent map when validating against older eligible anchors. Revert all note, occurrence and spentness writes with the branch.
- A single secret asset ID governs both sides of all token arithmetic. The circuit selects zero or that ID in each canonical note based on its token amount. It enforces that the common ID is nonzero exactly when any token amount is positive. Compute native and token sums in 66 bits and compare all sum bits. Native inputs equal native outputs plus the public fee. Token inputs equal token outputs. The maximum native right side is 3(2^64−1) < 2^66. Unregistered token creation is prevented by induction from authenticated credit policy and the separate legacy/migration/issuance rules. Outputs bind recipient-supplied A; the spender need not know a recipient's s. For the common transfer (5,11)+(7,23) funds receiver (4,13), change (5,21) and fee 3. Ordinary wallet shuffles output roles.
- Each swap side runs this same monetary relation with its separate input owner's secret, public kind, two real inputs/two real outputs, its agreed token ID or native-only policy, fixed recipient slot 0/change slot 1, fee 0 or 3 and fresh ephemeral approval key. The proof transcript authorizes exactly its public approval key and common terms commitment. Separate owner signatures enforce delayed joint consent. Neither wallet delegates its source secrets or proofs to a common prover. A signature does not grant spend authority on its own.
- Each party privately checks its outgoing values and change opening and *decrypts the counterparty's incoming output under its own key*, verifies the asset, amount, owner, occurrence slot and commitment, checks both proofs, matching terms, expiry, network and the unique native fee payer. It then signs the same joint SHA3-384 digest of both complete unsigned leg frames (including their real proofs, terms commitments, approval keys and expiry). Use the common architecture's terms/digest serialization, fresh secret terms salt and SLH-DSA-SHAKE-128f context. Per-instance proof challenges include all unsigned leg fields other than proof bytes. The joint signature binds both proofs afterwards; there is no cyclic hash dependency. Verify both signatures, the pair adjacency/ordering, agreed fees and current spentness on one branch. All four outputs, four NFs and one fee must be installed or rolled back together. [FIPS 205](https://csrc.nist.gov/pubs/fips/205/final)

## Offline receiving and seed recovery

A fresh 48-byte backup is the only secret recovery input for this single-account/single-descriptor version. Derive s = SHAKE256(N3R1 || 10:u8 || network || backup,48 bytes). Independently derive 64 bytes using tag 11 for ML-KEM-1024.KeyGen_internal(d,z) in standard order. Raw 1,568-byte validated encapsulation key ek and A form the off-chain descriptor (version, network, A, ek). D = H(12,network,A,ek). Never transmit a recipient hint, public descriptor hash or plaintext opening in the ledger. The component uses RFC 9935's seed-only representation to regenerate the same native key from d,z. [FIPS 203](https://csrc.nist.gov/pubs/fips/203/final) · [RFC 9935 §6](https://www.rfc-editor.org/rfc/rfc9935.html#section-6)

For a new spend, context X = H(14,network,kind,ordered-by-wire NF0,NF1,slot,output C). For an authorized credit use the distinct context H(15,network,creditID,slot,C). Encapsulate freshly to the validated ek obtaining shared secret K and ciphertext ct. Let aad = H(13,X,ct). HKDF-SHA384, IKM K, salt D and info aad, yields 44 bytes. Use the first 32 as AES-256-GCM key and last 12 as nonce, aad as associated data, 16-byte tag. The fixed envelope is ct[1568] || encrypted plaintext[144] || tag[16]. With an honest wallet independent encapsulations and 48-byte note salts are required, including for change. Deterministic repeated encapsulation under an identical descriptor/context reuses key/nonce; this construction offers no nonce-reuse guarantee under faulty payers. Pin context computation to the final ordered NF pair and output commitments before encryption. Signing/FS additionally binds the exact ciphertext bytes; ciphertexts stay outside the spend circuit. Recipients authenticate and recompute C and A before crediting. A malicious payer can burn its own funds by deliberately encrypting an unrelated opening. It cannot make an honest recipient credit it; a swap must refuse final consent. [RFC 5869](https://www.rfc-editor.org/rfc/rfc5869) · [SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final)

Offline wallets download the same authenticated ordered history stream, recompute both O and the depth-40 root/count, and try every envelope for every retained receiving key. Local candidate plaintext is never released before tag and note checks. Track all matching occurrences, derive NFs from s, remove spent entries against authenticated history, roll back reorgs and retain/reconstruct membership paths. Complete discovery requires branch-complete authenticated scan data and locally reconstructible paths (e.g., a wallet frontier plus per-received-note updates, or replay all leaves); a peer omission or a later distinct backup cannot produce an authoritative balance. No expiry on a funded ordinary occurrence. Compromise of this seed reveals past recipients and lets an attacker derive live spend keys. Rotation or HD account discovery would require an explicit versioned recovery policy. The tested receipt-only restore recovered the opening, not a funded respend.

## Reproducible resource screen

From repository root, use the project-approved Node 24.22.1 installation for the optional receipt calibration. The deterministic price needs only Python 3. The C probe needs a C11 compiler and libcrypto headers.

```sh
python3 -B experiments/new-note/sha3/price.py | cmp - experiments/new-note/sha3/PRICE.json
d=$(mktemp -d)
cc -std=c11 -O3 -Wall -Wextra -Werror experiments/new-note/sha3/calibrate.c -lcrypto -o "$d/calibrate"
"$d/calibrate"
.tools/node-v24.22.1-linux-x64/bin/node experiments/new-note/sha3/receipt.mjs
```

The [proof transcript and analysis](PROOF.md) give exact fixed wire sizes and the scope of the assurance argument. The [component measurements](CALIBRATION.md) list actual receipts, modeled CPU/memory, archive, relay and recovery consequences.
