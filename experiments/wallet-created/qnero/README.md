# Qnero standalone wallet comparator

One ordinary unmodified native wallet call spent a funded laboratory note and paid a separate, initially offline wallet. Its single real transfer occupied **one of six** private-batch slots. The canonical extrinsic was **154,508 bytes**. One full successful binary payload copy at 100M included payments costs **15.4508 decimal TB/year** before shared block data. The pinned public network's normal block-length allowance admits at most **6.570M** such payments per 365-day year at its target interval.

## Measurement

Upstream is MIT-licensed DigitalGuards/qnero, commit `f04c91307837c0231668383bec76ba98d89d2652`. The upstream release pins, original lockfile and all cryptographic code were preserved. The wallet compiled with Rust 1.93.0, locked qp-plonky2 1.5.5 and the upstream documented native parallel feature. Four rayon threads ran on an Intel i7-8700K with twelve logical CPUs available. The wallet and verifier executables and the small additive test/example sources have pre/post hashes. Fresh OS-derived seeds, stores and backup lived only in a temporary, owner-private tmpfs directory. The recipient received from public history and a fresh wallet recovered the same note using only its copied seed. The dataset contains public proof, runtime-pinned verifier, public anchor and ordered public commitments. [Source](https://github.com/DigitalGuards/qnero/tree/f04c91307837c0231668383bec76ba98d89d2652), [pins](evidence/pins.json), [wallet measurements](evidence/public/wallet.json).

| Actual observation | Value |
|---|---:|
| Wallet setup including source-built circuits, padding leaf and release-verifier checks | 3.341 s elapsed, 7.98 process CPU s |
| `Wallet::prepare_spend` including local path, encryption, proof and wallet self-verification | 5.135 s elapsed, 18.64 process CPU s |
| Real leaf and blinded private-batch proving inside that call | 5.123 s elapsed |

The public-only process had no wallet secrets, host home, network or prover-selected code. The caller checked the verifier's BLAKE2b-256 against the pinned upstream release. The process decoded the extrinsic, checked the canonical proof with that verifier, fee, anchor, six-slot shape, both ordered output commitments and both ciphertexts' digest. Twelve distinct nullifiers appeared in the public statement. Only the two in the real slot enter settlement. Controls separately changed the proof and one ciphertext. The first receipt's `positive.json` measures the bubblewrap supervisor; the inside-namespace child measurement supplies actual CPU and a launcher-limited RSS value. [Public check](public_check.rs), [child metrics](evidence/public-process.jsonl), [controls](evidence/controls.stdout).

The wallet ran the upstream production `Wallet::prepare_spend`, `WalletProver`, local Merkle rebuild, RPC client, SCALE encoder, block-body authentication and wallet scan. Its RPC server was the upstream test fixture. Funding was a synthetic 1,000-step coinbase at height 1; the anchor held one real commitment at height 2. Exactly one input was funded, the second was a dummy. There was one recipient output and one change output, freshly encrypted in random order. The fixture included the encoded extrinsic for the recipient's scan and the wallet checked its block-body root, trie data and note opening. The original measured run manually populated the fixture's post-payment history. Its producer receipt does **not** establish FRAME dispatch, PoW or a mined block.

## Bytes across roles

| Where bytes go | Direct default path |
|---|---|
| Local only | Note openings, spend and viewing keys, blinders, path, non-hiding leaf proof, padding and recursive prover state. The leaf proof never crosses the wallet boundary. |
| Submitted | 150,908-byte private proof including 131 eight-byte public field elements. Two 1,792-byte ciphertexts make 3,584 bytes. SCALE framing is 16 B: outer length 4, bare preamble 1, pallet/call 2, proof length 4, output-vector count 1, two ciphertext lengths 2 each. |
| Wallet → ingress | Actual `author_submitExtrinsic` JSON-RPC body 309,091 B (hex and request envelope). Before submission, 11 local path/profile preparation request bodies totaled 1,513 B. Funding synchronization added 2,150 B separately. The harness issued one 64-hex-character block-hash *response* for forensic readback outside the prepare/submit counters. HTTP, TLS, inclusion polling, retries, DNS, peer gossip, inbound answers and lower network layers are outside those request-body counts. |
| Relay before inclusion | Each peer requiring one full object needs its proof and both ciphertexts; the binary object is 154,508 B before protocol-specific control/framing. Relay to several peers multiplies this copy. No public P2P transfer was measured. |
| Final block and archive | Direct submission contributes the same 154,508 B of extrinsic data, once, with the proof, fee/anchor/slot public inputs and encrypted outputs. The public verifier is a static 1,749 B release artifact, not a per-payment append. Full SCALE block also has a vector, header with parent/number/state/extrinsics/commitment roots and digest logs including mining data, plus other extrinsics/inherents. Shared sizes depend on that block; a full consensus block was not serialized in the comparator. Events and current state are separate obligations. |
| State and subsequent verification | Two real-slot nullifier marks, two commitment leaves, creation heights, tree and fee accounting. A padding slot's zero commitments identify it; ten padding nullifiers are transported but skipped by the pallet. The digest binds ordered ciphertext bytes externally; public validators check them along with proof and applicable state. Zero ciphertext retention in state, so current state alone cannot recover delivery. |
| Receipt and recovery | Actual independent recipient scan issued 13 JSON requests/3,190 B, backup-only scan 12/3,058 B in the tiny fixture. Their input history contained the full public payment. Real native wallets read whole relevant block bodies with hex-encoded extrinsics, authenticated against the accepted header, and trial-decrypt; they do not get receipt-only 3,584-byte scans from this API. |

The public inputs already in the proof contain the anchor hash and height, two nullifiers, two commitments, public fee and ordered-ciphertext digest per slot. The public output count/positions, transaction timing, anchor age, fee, sibling outputs and linkage to the nullifiers are observable. No payment amount or identity is intentionally exposed by the wallet payment. Shield entry payer/amount and coinbase value are public. One funded commitment gives no empirical anonymity set in the run. The capacity is a sorted quaternary Poseidon2 tree with 20 levels (`4^20 = 2^40` leaves); historical webpage language about 16 levels differs from the pinned code. A path authenticates membership; the sorted hash alone does not authenticate position. The wallet uses authenticated storage to bind those positions. [Wallet source](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-wallet/src/wallet.rs), [runtime rules](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/chain/pallets/shielded/src/lib.rs), [profile](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/docs/PROTOCOL-PROFILE.md).

Shielded authorization proves Poseidon2-derived ownership, occurrence membership, nullifiers and bounded conservation. ML-KEM-1024 plus ChaCha20-Poly1305 encrypts ordinary notes. The private batch uses row blinding; the optional non-hiding public batch only sees blinded proofs. The proof transcript uses original Poseidon over Goldilocks, degree-two extension, two challenges, FRI rate 1/8, cap height 4, 28 queries and 16 grinding bits. The upstream configured target is 100 bits. The fork's original-Poseidon caveat, Fiat–Shamir, QROM knowledge/soundness, blinding and recursive composition remain review obligations. The library, parameters and metadata differ from CP03. Private equality of value alone gives no amount secrecy against side information. RPC nodes see client address, timing and payment; long-lived viewing-key compromise can expose retained ciphertexts. Independent wallets depend on header/checkpoint provider for chain selection and freshness. No system-wide PQ, network privacy or production claim follows. [Upstream qualification](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/docs/CRYPTOGRAPHY.md).

An optional public wrapper takes up to 53 wallet private proofs, six internal slots each. Upstream reported a 237,544 B proof on an earlier chain run with **one** actual spend and 52 padding inners. Its historical 241,027 B extrinsic predates current mandatory ciphertext sizing. That sample gives no measured 53-payer or 318-payment occupancy. With 53 separate one-payment wallets the builder must first acquire 53 complete standalone proofs and 106 ciphertexts. Even a fully occupied public inner region cannot amortize the 150,908 B each wallet sent to the builder. Direct measured accounting below credits one payer only. [Upstream benchmark](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/docs/BENCH.md).

## Reproduce

Linux x86-64, rustup with 1.93.0, an ordinary C toolchain, Python 3, bubblewrap/user namespaces, /proc and /dev/shm. Run in this directory. The upstream tree may contain only the two listed comparator overlays. The output directory must be new.

```sh
git clone https://github.com/DigitalGuards/qnero.git /tmp/qnero-wallet-src
git -C /tmp/qnero-wallet-src checkout --detach f04c91307837c0231668383bec76ba98d89d2652
rustup toolchain install 1.93.0 --profile minimal
python3 -B run.py /tmp/qnero-wallet-src /tmp/qnero-wallet-output
python3 -B measure_public.py /tmp/qnero-wallet-output/public /tmp/qnero-wallet-src/target/release/examples/public_check
python3 roles.py
```

The checked-in `evidence/public/payment.scale` is the full public transaction. The duplicate raw proof generated by the runner can be extracted as bytes `[11:150919]` from that extrinsic; its digest is recorded separately. To check the published transaction instead of the newly generated one, pass `evidence/public` as the first argument to `measure_public.py`. [Full producer](comparative_wallet.rs), [run harness](run.py), [role economics](ROLES.md).

**Extension boundary.** The current encrypted-note format fixes asset ID zero. The shielded relation and fee rule conserve one native asset, under one wallet's ownership keys. Native public batching verifies already independently authorized payments and the pallet may skip one stale/conflicting segment. That behavior does not implement atomic exchange. A private token payment with a native fee would need an asset-bound commitment/nullifier/receipt format, per-asset conservation and typed issuance plus a fee paid in native units. An atomic two-party swap would additionally need two distinct authorizations bound to the same negotiated legs and a settlement rule that commits every leg or none. Neither feature was exercised in this comparator. [Encrypted-note code](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-notes/src/encrypt.rs), [settlement source](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/chain/pallets/shielded/src/lib.rs).

**Additional FRAME acceptance.** A fresh second ordinary wallet payment with the same occupancy/widths also passed the pinned shielded pallet's external admission, pre-dispatch and normal dispatch. Real library code minted the corresponding synthetic funding, the anchored commitment tree matched, fee accounting and two new output paths matched, and a replay was refused. Full public artifacts and precise limits are separate from the first wallet-only timing. [Native FRAME replay](pallet/README.md).

**Complete wallet HTTP path and block encoding.** A third, two-funded-input payment went through normal preparation, submission, inclusion and nullifier confirmation. Observed HTTP was 314,635 B from the initialized sender (318,896 B including its separate funding sync). Of that, the single transaction POST was 309,227 B. The offline recipient and the backup-only wallet each sent 5,770 B and received 329,323 B. Encoded native transaction notification size was 154,509 B. The complete laboratory block encoded to 154,680 B with its own 171 B header. [Measured request-line, header, body, confirmation and block breakdown](http/README.md).
