# A CDHZ compiler registration for the funded EAR1 relation

The primary projection takes **257,045 bytes for a worst-case proof, 261,035 for an ordinary payment and 290,963 for one signed swap leg**. The signed leg exceeds the experimental 262,144-byte envelope by 28,819 bytes. A 16,384-leaf geometry brings the signed-leg projection to 253,855 bytes while multiplying the number of base-field polynomial evaluations at the wallet by 4.65. Both settings retain the open monetary extraction and privacy questions. Neither has produced an end-to-end compiled payment. The rolling transcript in earlier experiments is replaced here by the March 2, 2026 CDHZ construction with explicit per-round commitments. ## Interactive protocol and registration

Take an explicit input `x` with four suite bytes `EC01`, a 32-byte funded genesis pin and the 526-byte monetary statement. The wallet and ledger derive that statement under the new suite from the two commitments, nullifiers, owner authorization, policy, selected history and role-bound envelope as in the existing funded construction. A signed leg additionally binds the pair's terms, ephemeral key and expiry. An accepting terminal instance is a single true bit with the empty witness. Its relation is monotone. There are no implicit instance strings at input or output, hence no implicit-instance commitments, openings or extra proof-oracle queries by the final relation decider. The monetary predicates and their note and public-history primitives remain a separate relation environment. A concrete suite still needs coordinated dispatch by wallets and nodes. `EC01` is a model registration, separate from published EAR1 or SGM1. [Funded monetary relation](../structured-keccak/payment/monetary.py) · [EAR1 public record](../sgm1-security/evidence/EAR1_PAYMENT.json)

Use the existing 99 Keccak permutations, including 80 hidden Merkle parents, 783,808 binary coordinates, 6,065 scalar rows, 61,941 linear rows and 584 wide-field trace masks. The base field is F = GF(2^16) and the challenge field is K = GF(2^256) with the existing registered embedding. The primary DECS profile has N=4,096, packing s=91, t=60 opened columns and η=75 masking rows. Its 58,876 base symbols occupy 647 rows with one zero-filled coordinate. It includes 256 Artin–Schreier pads and 16 additional pads, each with a committed square. Private row extensions use 647 × 60 independent base symbols. The low/high mask chunks include 16 × 60 fresh overlaps and separate zero-sum quotient masks with 16 × 241 free base coefficients. The 75 independent DECS masking rows each have 151 values. All these private masks are represented within the existing trace or committed columns. Their randomness is distinct from the compiler salts. [Ring packing](../structured-keccak/ring/ring_switch.py) · [Mixed backend](../hidden-membership/smallwood/mixed/backend.py)

Round 1 sends a 4,096-cell oracle, one 1,508-byte base-field column per position. Its 754 entries are the 647 packed rows, 32 mask rows and 75 DECS rows in the original order. Its first public coin consists of 75 × 679 independent 16-bit entries of Γ. Round 2 commits the entire 22,650-byte explicit early degree table as one cell. For rounds 2 through 215 each prover string has length one over the common alphabet. Its cell concatenates consecutive short algebraic messages sent before the next fresh coins. The second round, for example, draws 640 bytes for the Keccak output and flattened indices; the next commits the masked output and first cubic message together. The last singleton contains the 7,744-byte mixed quotient. Every committed singleton is read at coordinate zero after the last coin; only the last selector chooses the 60 columns of the first oracle. The remaining logic runs on the opened answers. Thus all addresses are determined by public coins and x before reading any cell. In particular Γ changes the early degree table but never the set of addresses. The measured 215 rounds, maximum vector length 4,096 and proof query count 274 refer to symbols. The singleton answers together carry 49,626 bytes. [Run-length widths of every round](costs.json) · [Measured public schedule](../sgm1-security/evidence/EAR1_TRACE.json)

One common finite alphabet consists of byte strings of the registered widths, represented canonically by a two-byte length and that many bytes. The largest payload is 22,650 bytes. Fixed public widths determine the omitted length in each wire answer; any other length or trailing data is rejected. This also embeds injectively into a fixed-width padded symbol if the formal algorithm uses a fixed-width alphabet. The extractor's bit complexity must charge its maximum length. To complete the interactive protocol on every string, parse each coin using its round's registered widths and have the honest verifier reject malformed cells. Ordinary field coins are uniform bit strings in the original field bases. For the quotient point, one 96-byte little-endian integer modulo 2^256−8 indexes the ordered field elements outside labels 1 through 8. The final 120-byte little-endian integer modulo C(4096,60) indexes a distinct sorted subset by combinadic unranking. Both maps terminate for all public coins and honest algebra accepts every allowed choice. Each modulo map is within 2^-512 total variation of uniform, since its input has at least 512 extra bits. The shortest public coin is 256 bits. The longest is 15,856,896 bits. The bias is an additional comparison cost if a local bound assumes perfect uniformity.

## Compiler and authentication bytes

Use CDHZ Construction 11.7 with an independent FS function for each round and an independent vector-commitment function for each index. Honest commitment indices are 0 through 214; the verifier checks distinctness and range and uses the supplied index. Each VC uses a 640-bit ideal output and independent 512-bit leaf salts. Each round has a separate fresh 512-bit FS salt. Its FS query covers x, the ordered prefix of all commitment indices and roots, and the ordered prefix of all FS salts including the current salt. There is no rolling digest of the previous transcript. For round i the tuple serialization is x followed by the sequence of (index byte, root) pairs and then the sequence of salts through i. The round index is the function namespace. A concrete wire codec uses one byte per commitment index and two little-endian bytes per queried position. Counts, field lengths and vector lengths follow from the registration and the fixed expected query sets. Each supplied sorted query set must equal the oracle verifier's recomputed set. The salts and commitment roots are transmitted, and the verifier recomputes all coins. The model treats the prescribed random functions as ideal. A 640-bit output from SHAKE256 still uses a 512-bit-capacity sponge. The wider output alone does not instantiate a 640-bit ideal-RO security claim. [CDHZ, Construction 11.7 and Theorem 11.3](https://eprint.iacr.asia/2025/2166.pdf)

CDHZ Definition 8.2 hashes the pair (cell, salt) at each leaf and the ordered child labels at each parent under that tree's function. Encode the leaf input as ASCII `L`, a two-byte little-endian length, the cell and the salt; encode the internal input as ASCII `N` and the two digest labels. There is no leaf index in that input. A wire record contains the index, root, FS salt, sorted positions, answer bytes, leaf salts and finally the additional digests in ascending heap index. Use 1 for the root and N through 2N−1 for leaves. A literal query proof includes the queried leaf label and salt, both labels at each branch level and the root again. Depth-zero singleton proofs also repeat their root. Our codec sends the known commitment root once. For every occupied internal node of the first tree it sends both child labels once, in public heap order. For the singleton openings, the existing commitment is the expected leaf hash. At decode time all queried leaf values, salts, expected leaf hashes, intermediate hashes and sibling hashes are present simultaneously. The verifier can construct **all CheckIO inputs and expected outputs before any hash evaluation**. Compressed acceptance maps deterministically to acceptance of the expanded CDHZ proof, with no extra oracle queries. This is a restriction to proofs with consistent repeated labels and preserves every honest proof. A tiny deterministic executable control checks equality of both OutputIO tables and rejection of a changed label. At internal depth j there are at most min(2^j,t) occupied parents. The maximum over all 60-subsets is attained by spreading the positions across distinct prefixes at depth six. Across depths 0–11, 423 occupied parents then require 846 child labels. A contiguous, aligned cluster attains the minimum of 66 parents, or 132 labels. Both configurations have nonzero probability under the fixed selector. The size bounds use extremal sets. The proof length can thus reveal its public subset geometry.

An ordinary envelope adds 3,990 bytes, including both receipts, the authorization field, public prefix and proof length. A signed leg adds 33,918 bytes, including the 136-byte role extension and 29,792-byte final SLH-DSA-SHAKE-256s signature. A two-owner bundle adds 20 framing bytes to two complete signed legs. At the primary worst case this gives 261,035 B ordinary, 290,963 B signed, and 581,946 B per bundle. Literal alternatives are 352,395 B, 382,323 B and 764,666 B respectively. Proof bytes are projected for both swap legs using the same funded circuit shape. The separately pinned receiving-descriptor preflight has its own traffic: the two owners generate two more SLH-DSA signatures and each receives both, totaling 178,752 raw signature bytes across the coordinator pipes per swap before hex encoding. ## Wallet and node work

The primary wallet constructs 4,096 columns covering 3,088,384 base-field polynomial evaluations; keeping the serialized columns takes 6,176,768 bytes. Straight dense interpolation at 151 points entails 466,345,984 base-field product terms, before the separate 7,689,675 Γ table terms, the GKR/AS arithmetic, encoding and receipts. These are algorithmic work counts; optimized field kernels may reuse work. The compiler computes 8,405 leaf or internal hashes, draws 275,840 bytes of independent leaf salts plus 13,760 bytes of FS salts, and can store all tree labels in 672,400 bytes. The wallet also computes the IOR query schedule and legitimate answers. The node runs the 215 FS queries and up to 994 classical CheckIO queries for a total of 1,209. It also evaluates the actual GKR, trace, ring, Q and degree predicates. For example it processes 3,055,500 Γ-column terms, 679,500 degree interpolation terms and 14,520 wide-field quotient terms. It derives the public statement from an eligible local anchor, checks both final bundle signatures, conflict rules and the atomic state transition. Both signers verify both incoming proofs, check that the incoming receipt recovers the agreed spendable amount, then sign the ordered pair. Private note creation, nullifiers, two receipt seals and the local funded path search remain wallet work; public spending checks, receipt transport and ledger updates remain node work. [Measured underlying funded circuit](../sgm1-security/evidence/EAR1_PAYMENT.json) · [Ledger](../sgm1-admission/ledger.py)

Each compiler role consumes 2,109,522 bytes of meaningful round randomness; a literal implementation materializing the fixed maximum codomain at every round produces 426,154,080 bytes before slicing the needed prefixes. Independent variable-length random-function prefixes give the same honest view. Neither coins nor the full FS inputs are sent as extra network messages. The 215 full FS tuples contain 3,487,730 input bytes per role under the stated fixed x and index widths, before implementation domain tags or padding. The measured EAR1 reference used 45.16 seconds and 322,132 KiB at the wallet, 2.56 seconds and 133,536 KiB for a cold public check, and 2.14–2.20 seconds per warm check. Those observations used the existing EAR1 transcript, 64-byte tree outputs and 32-byte leaf salts. They are input evidence for the algebraic workload. There is no measured EC01 payment time, resident-set peak, throughput or native verifier speed. [Author measurements](../sgm1-security/evidence/EAR1_PAYMENT.json)

## Sensitivity and remaining assumptions

The same codec with 384/512/640-bit ideal tree outputs yields maximum primary proof sizes of 223,093 / 240,069 / 257,045 B. Changing the output width also changes every applicable CDHZ Merkle error term. A separate arithmetic sensitivity holds N=4,096 fixed, uses 64-byte digests, and shortens both leaf salts and FS salts to 32 bytes. It subtracts 32 × (274+215) = 15,648 bytes from the 240,069-byte proof, yielding a 224,421-byte proof, a 228,411-byte ordinary payment, a 258,339-byte signed leg and a 516,698-byte bundle. This would clear the signed envelope by 3,805 bytes. The ideal Merkle terms alone for σ=512 lie below the standalone one-quarter slack at the 2^128-query comparison; the algebraic RRBR contribution still has no such bound. Joint privacy of the shorter salts with adaptive protocol queries, many commitments and the wallet/receipt transcript is open. This arithmetic gives no concrete-instantiation or transaction-privacy guarantee. Separately, the model searches power-of-two N from 512 through 32,768, s in [15,300], and t in [10,239]. For each admissible geometry it takes the smallest η for which C(N,s+t+1)/2^(16η) ≤ 2^-256; it also requires C(2s+t−1,t)/C(N,t) ≤ 2^-256 and disjoint evaluation and interpolation points in F. Cells must fit the registered two-byte length. These are two local DECS tests on fixed objects. The scan compares maximum wire sizes only. At N=16,384 the grid winner (s,t,η)=(77,39,79) uses 14,352,384 field evaluations and gives a 507,730-byte complete two-owner bundle. At N=32,768 the grid winner (80,34,85) uses 27,951,104 field evaluations and gives a 486,670-byte bundle. These projected parameter sets preserve the round pattern, fixed witness, wide field and masks per opened column. They need their own funded implementations, verification and proofs. [Finite grid, work and bounds](costs.json)

The compiler's theorem requires the complete adaptive IOR knowledge-state implication, polynomial witness extraction at every accepting history and the lemma relating the relaxed representation to the funded relation. A decoder for suitable fixed cells and individual polynomial identity errors do not supply those premises. The CDHZ 6.10/11.3 coefficient on κ_RRBR is already about 2^264.32 at a global budget of 2^128 queries. Keeping that contribution below 1/4 needs at least 267 bits of established per-round error strength. The K=GF(2^256) implementation has individual degree factors (for example the cubic fold bound 3/2^256); these elementary estimates cannot certify that headroom. Its 256-bit minimum coin length also incurs a finite-challenge term. The 640-bit ideal tree and two 512-bit salts do not address this algebraic limitation. Choice of the monetary state and decoding threshold, how Q, Γ and the early table jointly imply that state, the hash instantiation for all domains, and privacy of the complete committed transcript with receipts and future spends require separate arguments.
