# Adaptive quantum extraction for an EAR1 funded spend

**CDHZ does not give a 128-bit authorization bound for the registered EAR1 packet.** The first degree challenge already comes from a different Fiat–Shamir construction. Even on a proposed wire implementing the paper's construction, the current 256-bit-field estimates do not establish a useful knowledge bound at $2^{128}$ quantum queries. Neither finding demonstrates an unauthorized debit.

## What must be extracted

Let $x$ contain the registration, the independently authenticated genesis/eligible branch context and the canonical monetary statement. Its 526 encoded bytes bind chain, root, count, fee, two nullifiers, two output commitments, intent and authorization digest. The verifier derives them from the approved anchor and envelope, including both complete receipt ciphertexts in the intent. A reduction taking the whole branch context as $x$ must account for the deterministic validation and projection to the bytes actually bound by EAR1. Two contexts equivalent for the NP predicate can have different current spent sets.

Take no implicit input oracle, $n_y=0$, and exact distance $\delta=0$. The input relation $R(x,w)$ checks the existing 6,155-byte money witness. For two real inputs it authenticates both ASK-derived owners, both typed funded records and occurrences, their distinct positions below count, both ordered paths to the selected root, the two NFs, both conservation equations and both outputs. The first ASK additionally binds the intent. In the one-real-input branch the scalar records are equal, both paths verify and the second NF uses its dummy tag. For two independently keyed grants the desired extraction includes an ASK preimage for each. On legal payments with common ownership the two ASKs may coincide. The relation does not require independent human negotiators, either KEM secret, or output-owner consent. The SLH approvals and recipient checks for a swap have separate predicates. Definition 10.3 concerns a *reduction between relations*. Its adaptive game lets the adversary output $(x,\pi,w')$. The output relation must hold on the verifier's output and $w'$. ## First failed construction premise

Theorem 11.3 applies to Construction 11.7. With empty implicit input, the prover commits to its first IOR string, selects the VC index, and draws the first verifier coins from the first independent FS function on $x$, the indexed commitment and the round salt. In later rounds the function for that round takes $x$ and the *whole* prefix of commitment indices, commitments and round salts. Every prover string receives its own indexed VC. The verifier reconstructs its queries, checks the VC openings and runs the IOR. In Construction 11.9 step 2(c) the reduction can parse a superposed FS input for its commitment arguments, apply the purified multi-extractor, and uncompute. This access matters to the proof.

## What the IOR still owes

The ideal first proof string holds 4,096 vector columns, with undefined extracted coordinates permitted. Another string supplies R. Compare $R(e_i)$ to the degree mask plus the challenged linear combination of row values at each available index. If no bad degree cancellation occurred, 151 consistent positions suffice to interpolate each degree-at-most-150 row. With fewer positions the conditional decoder uses a lower-degree interpolant and the chance of drawing 60 openable coordinates has to be charged. Evaluate the rows on the 91 packing points, unpack wire and mask coordinates, recover the bit IDs of both monetary records from the public allocation schedule, and test $R(x,w)$. Sixty disclosed columns alone cannot determine these polynomials even with fixed early R: shifting a row by a nonzero degree-60 polynomial vanishing on those points and compensating the corresponding degree-mask rows preserves those 60 column values and the degree equations. The Merkle root and full Q checks are additional constraints; this dimensional observation concerns only the degree layer. On one newly funded two-real-input fixture, a test-owned partial oracle supplied 152 positions. The decoder used 151 for interpolation, checked one more, recovered the original 6,155 bytes and separately rejected changing either distinct ASK. This is an honest-input decoder check. [Conditional degree argument](../sgm1-security/REDUCTION.md) · [Measured decoder and 60-column experiment](decoder.json)

Definition 3.5's knowledge state takes a candidate witness as an argument. Initially it tests the input relation. At the end it tests the output relation. A prover move cannot rescue a false state for the same candidate witness. At each verifier move, Definition 3.6 requires a deterministic polynomial-time extractor transporting the succeeding witness to an acceptable preceding state except for probability $\kappa_i$, **even when that witness is chosen after seeing the challenge**. An upper bound for fixed honest witnesses does not establish this quantified property.

A sufficient intermediate result for the trivial output relation is a complete CMS-style prefix state for the *same* ideal IOP, with deterministic efficient extractor $E_0$ before a coin whenever rescue probability exceeds $\kappa_i$. At a non-final prefix set the CDHZ knowledge state to “the supplied witness satisfies $R$, or the CMS state is alive.” At the end require acceptance and the unit witness. Transport an already valid input witness unchanged. For every other witness run $E_0$ on the prior prefix, without evaluating the possibly inefficient CMS state. If that state was alive, any predecessor witness passes. When an intermediate or final state accepts some witness and this transport fails, the prior CMS state was doomed, the challenge rescued it, and the prior extractor failed. This event has probability at most $\kappa_i$ by the assumed CMS property. The CMS initial/prover-move rules imply the required initial/prover-move rules. This conditional argument explains how the two definitions can meet. No complete CMS state for EAR1 is supplied here. It would have to cover masked Keccak, selectors, scalar predicates, quotient, ring squares, Q and all partial-column patterns together. The chronological classical hash-query extractor in SmallWood+ is a different object. ### The custom terminal in the knowledge state

After the 120 cubic chi, 55 quadratic linear-map, 12 cubic order and 13 cubic scalar folds, the verifier batches the public wiring (1,982,112 coin bytes on the released geometry). It reads a 256-byte quotient for eight terminal products, challenges outside their eight nodes, reads a blinded 32-byte evaluation and draws 576 bytes to compress the bit and trace residuals. For a fixed false polynomial already determined before each coin, the fold-only union costs at most 545/2^256. The eight-product identity has the local estimate 15/(2^256−8). These statements assume the same fixed assignment throughout. [Chronological bounds](../sgm1-security/REDUCTION.md) · [Registered labels](../sgm1-security/evidence/EAR1_TRACE.json)

The terminal reveals 256 masked base-field projections (512 bytes), checks their absolute traces against the 256 target bits, draws 256 wide coefficients and receives one blinded wide scalar u. It draws 258 more wide coefficients (g, s, t), combines the projection, square and pad constraints and asks the mixed commitment to open to the target sum(g × embed(projections)) + s × u + t × u² in characteristic two. The 7,744-byte mixed Q precedes the final 60-column selector. Openings must authenticate all those checks against the same partial-column state used for the early degree table. For every possible prefix, a successful backward extractor must either keep the predecessor witness or charge a quantified bad coin. A correct local trace or a separately valid square equation gives no transport for an adversarially changed decoded assignment. ## Quantitative consequence for the full-prefix candidate

This is a **conditional calculation** for the proposed normalized compiler. Take $k=215$, $q_\Pi=274$ (60 column coordinates and 214 singleton message coordinates), $\ell_{\max}=4096$, $q_V=1209$ charged oracle calls under the proposed explicit opening schedule, $r_{\min}=256$, Merkle digest width $\sigma=640$, and leaf and round salts of 512 bits. Group consecutive messages consistently and fix all rounds in advance. For a $b$-bit uniform integer reduced modulo a range of size $M$, the largest point probability is $\lceil 2^b/M\rceil/2^b$. Fixed-length subset unranking and quotient-node exclusion can use that bound for their new interactive errors. The normalized sampler requires its own correspondence. Let $T$ be the adversary query bound and $a,b,c$ its FS, VC and multi-extractor query masses, with $a+b+c\le T$. These are superposition query masses. Let $Q=q_V$, $D=q_{\widehat{CR}}+q_{\widehat{CR}'}$, and $\kappa$ be a **proved** maximum per-round Def. 3.6 error over the statement set. Theorem 6.10 gives a state-restoration upper bound

$$
S(T,a)=80(T+k+1)(a+k)\kappa+(T+k+1)k\,2^{-r_{\min}}.
$$

Theorem 11.3 includes $4S(T,a)$, offline and online extraction errors, and a verifier commutation term. Using Theorem 8.3 and upper-bounding both readings of the online VC query mass gives this conservative expression for the extraction error:

$$
\max_{a+b+c\le T}\left[
4S(T,a)
+\frac{8\,[160 b(2T+1)^2+16q_\Pi\log_2\ell_{\max}]}{2^\sigma}
+\frac{4\cdot240\max(c+1,b+D)(T+1+Q+k+D)^2}{2^\sigma}
\right]
+\frac{2Q^2\cdot240(T+2+k+Q)}{2^\sigma}.
$$

Definition 7.3 and Lemma 11.10 assign the online loss to VC query mass. Theorem 8.3 displays the VC and multi-extractor arguments in a different order. We cover both positional readings with the maximum above. The executable uses $T+1$ for this mass when $D=0$.

There is also a separate Def. 10.3 commutativity error bounded by $240(q_2+1)/2^\sigma$. The admissible Merkle extractor in Theorem 8.3 takes $O(k t\ell_{\max}(\log|\Sigma|+\nu+\sigma))$ time for its own argument $t$. Theorem 11.3 additionally invokes the state-restoration extractor. This cost matters when turning witness recovery into a bound on work for a secret.

Then $D=0$ for those interfaces. The money predicate still incurs real computation. ## From extraction to authorization

The adaptive theorem allows the adversary to select its statement in the specified oracle game. A debit against an honest funded note is a further game. The reduction must generate or justify the funding history, simulate allowed wallet/receipt observations and charge their queries. It must exclude valid prior approvals and retries and identify the debit on the actual branch. Given a legal witness for an unauthorized target debit, it must show that a recovered ASK opens the targeted occurrence or charge a separate owner/commitment/tree/NF binding failure. A different opening that satisfies the same NP relation is a cryptographic case. Current spentness and atomicity are ledger premises.

Real prior payments cannot be supplied as unexplained auxiliary advice correlated with the same random oracle: the reduction must give the extractor's experiment the appropriate generation process or establish an auxiliary-input or one-more result. Recovering either of two targeted secrets, recovering both independently generated secrets, and finding any vulnerable note among many funded notes have different probabilities. Two record slots give no automatic multiplication of security levels.

**Disposition.** EAR1's early R removes one preimage obligation. CDHZ supplies an adaptive theorem for a specified compiler, a relevant salted-Merkle primitive in its ideal model, and a quantitative screening inequality. The first FS query in exact EAR1 fails the construction identification. The normalized candidate still needs a whole-money relaxed-RBR argument, an implementation-to-oracle correspondence and a funded-target reduction with an adequate concrete budget. These results do not authorize a funded activation or establish receipt anonymity.
