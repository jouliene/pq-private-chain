# Structured Keccak GKR for linked FS01 parents

The prover executes all 24 Keccak-f[1600] rounds and proves the round transitions as a single batched layered circuit. The independently registered verifier derives the same maps, round indices, coefficients, domain separators and SHAKE padding from its statement. Two adjacent hidden parents have produced 94,554-byte proofs at flattening factor K=24 and 107,106 bytes at K=4. K=4 exercises the second sum-check that connects successive layers of the GKR reduction. The component statement establishes a hidden ordered path segment to the expected root. Funded ownership, nullifiers, position eligibility and value conservation require their own enclosing constraints. ## Structured circuit and transcript

For P permutation instances and a chosen divisor K of 24, divide each permutation into K consecutive groups of D=24/K rounds. Commit to the input, the K−1 intermediate boundaries and the output. A group's terminal state and the following group's initial state use exactly the same 1,600 witness bit coordinates. The batched layers have a 2,048-position state axis x and a padded group axis z of size 2^ceil(log2(PK)). Coordinates at x≥1600 or z≥PK have value zero. The batch code accepts *any* positive P, including non-powers of two. A prover keeps the full 25 states for computation; it commits only to the selected K+1 boundaries. Keccak lane order is x+5y with 64 bits per lane and bit 0 least significant.

For each active state bit, the previous state's three linear images O,L,R each XOR eleven indexed inputs. They apply theta, rho and pi and select the three neighbors required by chi. The next bit is C + O + (1+L)R, where C is the public iota bit for the actual round in its flattened group. The verifier precomputes the fixed maps independently; it does not expand the product into 121 monomials or commit to the three images. A fresh pair of public challenges specifies the initial output MLE. A masked output value is bound to the packed committed boundary bits. [Round maps and GKR](rounds.py)

* **Outer sum-check.** At each of D backward layers, subtract the public iota MLE from the expected state claim (XOR in characteristic two). Use a degree-three sum-check over 11+ceil(log2(PK)) variables for the equality-weighted expression O+(1+L)R. The prover sends three masked evaluations per variable, then three masked endpoint values. The verifier records one quadratic trace identity equating the final affine sum-check claim to the public equality factor times the gate expression.
* **Interior reduction.** At each of the D−1 interior boundaries, combine the three endpoint values with three independent challenge-field coefficients. All three linear maps act only on x. Hold the group coordinate z fixed at the last sum-check point and run a degree-two sum-check over the 11 state-address variables for the product of the transposed map weights and the previous state's MLE. The prover sends a masked claim for that previous state; the verifier checks it times the public endpoint map weight equals the second sum-check's endpoint. This choice costs 23 mask coordinates per interior boundary and works even for zero endpoint weights. The resulting claim feeds the next backward layer. At the earliest layer, the verifier instead binds all three images directly by their public transposes to committed input boundary bits.
* **Private ordering.** For the 32 packed GF(2^16) chunks of each parent, the single committed direction bit times (child+sibling) must equal left+child. A separate degree-three sum-check batches these products. The inversion-free trace identity and three endpoint bindings refer to the same bit addresses as the permutation input. A linear check enforces right+left=child+sibling across all 512 positions. The first child comes from the private segment opening, and later children alias exactly the first 512 output bits of their predecessor. The 24 prefix/level, 40 suffix/padding and 512 capacity bits are fixed, as are all 512 public terminal bits per path. Higher output bits stay hidden. [Parent wiring](parents.py) · [Packed placement](selection.py)
* **Trace authentication.** Compiler 1 section 3.2 jointly linearizes the D+1 quadratic identities from the permutation and selector gates. It interpolates masked products over distinct field points, samples the test point outside the original product nodes, and checks two new affine identities. All previously registered fixed, terminal and internal claims enter a randomly weighted joint binary functional. A single packed ring commitment authenticates the functional and the associated affine combination of the trace masks. The joint witness and masks are committed before the first GKR challenge. The ring module documents its local field-trace construction and assumptions. This suite uses its own transcript and mask/check schedule. [Masked compiler](cbip.py) · [Ring backend](../ring/)

For H paths with P total parents, the component's binary witness has 512H + P(513+1600(K+1)) coordinates. The externally visible trace uses

```text
ell    = 11 + ceil(log2(P*K))
ellSel = 5 + ceil(log2(P))
trace  = 1 + D*(3*ell + 3) + (D-1)*23 + 3*ellSel + 3 + D + 2
```

Each trace coordinate corresponds to 32 transmitted challenge-field bytes. The last D+2 corresponds to joint product linearization. Add the ring module's `wire_bytes(nbits,trace)` for the complete proof; the separately provided SGP1 expected statement costs 6+66H bytes. These formulas count this implementation, including padded axes and uncompressed path siblings, and do not count a complete payment. The tests establish algebraic consistency in the tested cases; no parameter setting here establishes end-to-end quantum knowledge or privacy. The ragged three-permutation K=3 case used two paths of depth two and one, nine active groups in a 16-group padded axis and eight backwards layers. Its proof was **116,226 bytes**, with 2.985 s proving and 0.361 s public verification. A new process separately rejected a mutation in each frozen root. A six-permutation, two-root K=3 smoke check also verified at 119,370 bytes (4.736 s proving, 0.424 s verification). The clear kernel regression covers K=1,3,8,24 and four private corruptions; its outcomes are distinct from complete commitment-backed proofs. ## Registered roles and reproduction

The verifier's SGP1 statement is ASCII SGP1, u16 little-endian path count and, for each path, one-byte starting level, one-byte positive depth and expected 64-byte root. Each starting level plus depth must be at most 40. The standalone calibration CLI supports up to 256 parent permutations per invocation. The verified program and flattening factor are supplied locally. The verifier never accepts a circuit or expected root from the proof packet. The private input for each path is one initial 64-byte child, followed by each 64-byte sibling and its direction byte (0 or 1). A path consumes 64+65*depth bytes from the private pipe. The diagnostic prover consumes one extra 64-byte value for the second parent's consumed digest while leaving the actual first output untouched. It emits a complete invalid proof; all verifier checks remain active.

```bash
run_dir=$(mktemp -d)
../../hidden-membership/smallwood/build-wide.sh "$run_dir/native"
PYTHONPATH="$run_dir/native" python3 kernel_checks.py
PYTHONPATH="$run_dir/native" python3 ragged.py
python3 ../harness/run.py "$run_dir/two" "$run_dir/native" 2 --flatten 24
python3 ../harness/run.py "$run_dir/eight" "$run_dir/native" 8 --flatten 4
```

The standalone public replay uses `PYTHONPATH=<native-dir> python3 role.py verify EXPECTED_STATEMENT PACKET --flatten K`. The calibration worker runs with CPython 3.12, NumPy, the pinned local wide-field extension and the project ring module. Its code accepts no prover-selected verification key.

The reusable `RoundBatch(boundary_ids, states=None)` takes integer witness positions of shape [P,K+1,1600]. Its optional prover-only state array has shape [P,25,1600]. `run_rounds(batch,ctx)` can therefore authenticate arbitrary fixed permutation inputs and outputs together. An importer supplies its own absorb/XOR constraints, sponge continuation, hidden index and message encodings. `run_products(ctx,ell,prover_arrays,bind_forms,label)` checks equality-weighted A·B=C residuals on a hypercube; the callback binds all three terminal polynomials to the same commitment. `proof.execute(statement,nbits,ntrace,build_constraints,...)` drives the commitment, circuit callback, joint linearization and public verification. Callers must register their own exact circuit, source and public statement encoding before proving. [Composition API](proof.py)
