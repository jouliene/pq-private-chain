# Reproduction from public main

A reviewer who wrote no implementation ran the complete milestone command from a new anonymous HTTPS clone. With user and system Git configuration, credential helpers and prompts disabled, the reviewer checked the actual remote URL, clean checkout and absence of Git object alternates. Public main and the detached tested HEAD both resolved to `9502266c7e976f16af47cb23a7104257dacf6968`. The previous milestone `4810fefa6bc8de48e0ad4adb6b8e881242793a7a` is its ancestor. Dependencies came from the public pinned download and the freshly built in-tree field source. [Tested code](https://github.com/jouliene/pq-private-chain/commit/9502266c7e976f16af47cb23a7104257dacf6968)

```sh
d=$(mktemp -d) && git clone -q --no-checkout https://github.com/jouliene/pq-private-chain.git "$d/src" && git -C "$d/src" checkout -q --detach 9502266c7e976f16af47cb23a7104257dacf6968 && bash "$d/src/experiments/structured-keccak/reproduce.sh" "$d/run"
```

The reviewer replayed the checked-in ring and two-parent packets and generated a second ring proof from fresh randomness. Its size was 83,866 B and its SHA-256 was `869c63b35e4a7406e820f68f6768f85962fff3ecb8bc40f38c63c03d7f560051`. All 65,536 base elements passed the trace/dual tests. All nine negative controls passed, including an inconsistent square opening.

The independent three-parent/two-root proof had 116,226 B. The verifier accepted all four leaf choices at the same independently computed root. It rejected a full-length disconnected proof, a changed public root, a changed proof and invalid framing. Independent mutations of the two ragged-batch roots also failed. The compiled monetary inventory regenerated byte for byte, SHA-256 `6de282c29456bffa9dbe70047237a50dd818ca984d16468c8796370e547e9559`.

The reviewer traced the complete circuit's private active slot, duplicate-record condition, owner/NF binding, shared index bits, both 66-bit sums and output type checks. Public SGM1 registration, signed funding replay, genesis and receipt binding were verified against the ordinary verifier. The clear coset and blinded square openings have explicit conditional masking arguments. Quantum extraction under the adaptive monetary transcript and joint receipt privacy still require analysis. The full ordinary proof, swap byte inventory and the existing consensus implementation are separate acceptance boundaries.


The SGF1 verifier independently checked a new signed funding prefix with 13 occupied positions, spending 2.10 user + 0.09 system seconds and peaking at 125,008 KiB. The prover used 38.36 user + 2.11 system seconds and 315,504 KiB. A valid alternate ordering of its two signed issues failed in 1.27 s. The proof SHA-256 was `2f6a4cb0cd6809783a0de3b31fd189505ae9a8b5ac475623e76b98dc4d3a9849`.

For SGM1 the reviewer generated another prefix, two inputs and fresh output keys. The complete ordinary wire was 183,224 B, SHA-256 `2f67935275df03ebee13a1c05814b2dafecfe4e2f44fffa05efbf44cd3590a27`. The new wallet prover used 38.92 user + 2.23 system seconds and 322,672 KiB. Fresh public verification used 2.25 user + 0.09 system seconds and 133,660 KiB. Three separate proof checks in one process consumed 1.978, 1.946 and 1.962 CPU seconds. Both recipient helpers opened their respective outputs from backup material, and changes to the fee, each receipt or the proof were rejected. The circuit had 783,808 bits, 584 trace masks, 6,065 scalar product rows and 61,941 linear rows. The full runner exited successfully and left the public clone clean. Its independently regenerated main cost file had SHA-256 `31af10331935a4c6da44c9ee0e5080e6178537ae4b61082fa9e393132d193c79`.

Using the fresh timing file with `costs.py --payment-metrics` gave 1.9542 CPU seconds per warmed proof (mean of the last two). The resulting crypto-only projections are 0.681, 2.043 and 6.812 cores for 10M, 30M and 100M included operations. Archive and relay sizes remain identical to the author's result.
