# Monetary review of the TKN1 research profile

**TKN1 conserves one fixed token and native fees under separate integer equations.** This conclusion applies to notes created by its authenticated test genesis or the registered TKN1 verifier. Each note has a single recipient and a single spend identity for both balances. Its initial supply is 400 synthetic native and 240 token units. After `k` accepted payments the sum of unspent native values is `400−3k`, and the sum of unspent token values is 240. The public ledger derives this invariant inductively from issuance, proof verification and current spentness. Lost keys or unusable receipts affect who can spend a note. They do not change its committed value. [Registered circuit](../candidate/profile.rs) · [Public state transitions](../candidate/ledger.py)

## From native authorization to two amounts

| Membership | Each real input’s recomputed `cm` reaches the private tree root in the header authenticated by public anchor/height. Both paths use a shared bounded depth, up to 20 quaternary levels. The host sorts children; the circuit uses private position hints. The circuit does not publish or check a selected-chain leaf index or count. | Same membership check and index privacy. The public ledger checks the particular height/anchor on its supplied history and enforces an eight-height window. |
| Dummy inputs | Safe Boolean, native amount times dummy bit equals zero, membership can be skipped, and `NF_DUMMY` is selected. Both nullifiers are published and must differ. Non-padding anchor needs at least one real input. | Explicitly constrain `token × dummy = 0` too. A single sufficiently funded real note plus one dummy can spend. | Outputs and fees | Output `rho` is derived from both input serials and the output index. Each amount and fee is range checked; the native public codec requires fee 3. | Same `rho` rule. Write `M=2^62−1` and `p=2^64−2^32+1`. If both sides of an equality between unsigned sums are strictly below `p`, equality in the field implies integer equality. DLF1's original input side is at most `2M`, its output-plus-fee side at most `3M` before imposing the fixed fee. In TKN1 both token sums are bounded by `2M`; native sums by `2M` and `2M+3`. All are below `p`. The note definition's comment about adding four 62-bit values does not extend this reasoning: `4M−p=4,294,967,291`. Adding four unrestricted inputs or outputs **per lane** needs smaller terms, an exact carry representation or another proven bound. [Pinned quantity width](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-note-core/src/note.rs#L7-L20) · [Exact maxima](BOUNDS.json)

For payee vector `(x,y)` and selected input totals `(N,T)`, the wallet must also fit both changes into one note: `0≤N−x−3≤M` and `0≤T−y≤M`. A large total balance can be fragmented across unsuitable notes. The test selector takes the requested prefix of a wallet's available notes. An output carrying only token value requires an additional native fee input on its next spend. An output carrying both can fund its own successor. One real nullifier consumes the entire mixed note. [Wallet selection and reconstruction](../candidate/wallet.rs)

The receiver's incoming viewing key holds the public spend key and KEM decapsulation key. It can open the receipt and reconstruct the committed vector. Spending additionally requires `ask,nk` corresponding to that same `pk`, and an unspent member at an eligible anchor. An independently generated spend seed derives both spend and viewing authority. The original payer knows the opening it created, but does not learn those spend secrets. The wallet skips unusable private openings while appending the authenticated public `cm` and checking the final tree root. TKN1's build redacts the repurposed field in both upstream debug printers. Public observers know the network has one possible token. The small, public initial allocation also limits anonymity. ## Supply, origin and version boundaries

Each approved 488-byte genesis has four public entries, with fixed allocations `(100,70),(100,50),(100,70),(100,50)`. Each entry contains index-derived context32, recipient pk32, both u64 amounts and cm32. The native helper independently derives genesis `rho` and `raw_r` from the first 80 bytes using distinct domains and reconstructs the typed commitment. The validator checks exact allocations, index context, distinct nonzero CMs, and the caller-approved SHA-256 of the **whole** genesis. The genesis state/body digests and tree root then enter the AP header. Hence public genesis authentication covers ownership and amounts without disclosing the spend secrets. The network ID binds the TKN1 verifier, PoW bits and anchor window. Different approved allocations to recipients have different genesis identities even on the same network ID. [Typed genesis and state](../candidate/ledger.py) · [Native endowment helper](../candidate/wallet.rs)

There is no subsequent mint, subsidy, miner-credit transfer, selectable issuance authority or asset registry on this test network. The three native units per included transfer accumulate in an unspendable fee sink. DLF1 native issuance and its separate zero-premine history remain unchanged. A future issuer registry must define unique canonical identifiers, authenticated issuance/caps, permitted burns, per-asset conservation, version activation and atomic rollback. A 256-bit byte identifier needs an injective encoding such as eight constrained u32 limbs; four Goldilocks limbs support a canonical field-digest namespace instead. A free u64 similarly needs a declared restricted subset or a multi-limb encoding. [Canonical digest decoding](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-note-core/src/digest.rs)

TKN1's outer commitment and nullifier conventions reuse Qnero's constructions with a typed inner opening. Monetary induction depends on **creation provenance**: every member must have been inserted by a creator enforcing both balances. Importing an untyped root or admitting DLF1 output creation into that tree would drop this premise. A bridge would need to prove an authorized conversion, enforce the correct initial token balance for legacy value and atomically consume each original note. All legal spend versions for the same note must derive the same real nullifier and consult a shared spent set. This prototype has no such bridge.

A scalar note per asset is a distinct choice. With one hidden non-native ID `T` and one native-fee input, a general fixed-role spend needs a token payee, token change and native change: two inputs, three output notes. The relations are `t_in=t_pay+t_change` and `n_in=n_change+3`; every input/output must open the required asset ID. Arbitrary-ID scalar transfers need an equality for each label in the union of **both** input and output sets and for NATIVE. Constrain grouping indicators against complete identifiers and charge the fee once. One publicly known token, fixed asset-role positions, and arbitrary hidden asset IDs offer different anonymity sets. The selected vector representation avoids identifier grouping by fixing the two assets at deployment.

## Registration and historic validation

The 1,481-byte TKN1 key has SHA-256 `f4b865c6c2aaa9afdd6a7a7ecb94fe9b76ffdc75d25d5a570cf595d315576c2b`. Registration records 468 gates before blinding, 4,096 trace rows, five quaternary folds and 26 public fields. DLF1 has the same key length and PI count, but a different key. `load` regenerates the TKN1 verifier from fixed source before accepting the supplied key. Public validation must use a trusted executable or independently approved source build. The registered D8C1 circuit verifies eight instances under the **constant DLF1 key** and authenticates an active prefix. TKN1 historical aggregation would require another proof, key, version/dispatch rule and commitment to the corresponding typed effects in the PoW core. A mixed wrapper must constrain its per-slot dispatch to fixed registered relations and bind the type/public effects through padding, public decoding and replay. Concrete quantum knowledge and privacy of the composition remain open. The successor's public state hash now commits the preceding **nonce-dependent work ID**, or a distinct genesis work-parent digest at H1. Our independent byte-level check recalculated each work ID, body and state digest from the four released raw blocks, checked those work links, and found eight distinct serials and a final native fee sink of 12. The construction run reported four 143,187-byte packets with 2, 2, 2 and 1 real inputs. The final recipient restored a single mixed note `(41,75)` and used that note plus a zero dummy, an independently funded example of one-note spendability. The test ledger processes a supplied ordered stream in memory. Competing-branch selection, durable reorg handling and TKN1 certificate pruning need separate execution.
