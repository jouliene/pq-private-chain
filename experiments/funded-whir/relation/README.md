# Funded transfer constraints over Goldilocks

The two public matrices describe a two-input, two-output ordinary MNG1 transfer and a single SLG1 exchange leg. The matrix field is the released wallet field, p = 2⁶⁴ − 2³² + 1. Both programs use the same registered funded notes and private tree depth limit of 20. The ordinary profile accepts zero public supply change and fee 3. The leg accepts a fee of 0 or 3 and requires a real first input. The surrounding signed swap validator owns ordered composition of both legs, aggregate fee, deadline and both final authorizations. These matrices do not authorize standalone swaps, register assets or prove mint and burn operations. ## Statement and witness

Public fields in **zero-based** order are the anchor limbs 0–3, height 4, two nullifiers 5–12, two ordered commitments 13–20, fee 21 and ordered ciphertext digest 22–25. Ordinary transfers require all five supply descriptor words 26–30 to equal zero. For a leg, words 26–33 are the eight little-endian u32 words of its ephemeral signing public key. Columns start with ONE, followed by every public word in this order. Each field must have a canonical u64 encoding below p.

The private memory-only input has `suite`, the complete `public` array, 45-word `header` in native preimage order, `depth`, a 4-word `asset_id`, `fee`, `delta` and a 4-word `ct_digest`. Both entries of `inputs` contain `ask`, `nk`, `rho`, `raw` (four words each), `value`, `token`, `dummy` and per-level `siblings` (three four-word digests) and `positions` (0 through 3). Each output contains `pk`, `value`, `token` and `raw`. SLG1 additionally supplies `auth_key` as eight u32 words. Inputs carry the recoverable typed opening's raw randomness. SLG1 outputs carry the randomness before binding their authorization key. The actual wallet supplies already-reduced header state and extrinsics root words according to its existing codec. [Header preimage](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/header.rs)

* The circuit hashes the entire header with additive Poseidon2, binds its height to the public 32-bit height and its hash to the public anchor. Input ask and nk derive ak and pk. The note commitment binds pk, rho, typed opening and the native amount. Every input publishes its nullifier computed from nk, rho and the typed opening under the real or dummy domain. A limbwise equality check rejects repeated nullifiers.
* Boolean dummy flags force both native and token quantities to zero on a dummy. Every accepted transfer has a real input. For the ordinary profile fee 3 already excludes the upstream all-dummy padding case. Twenty monotone Boolean flags sum to the common depth. Per level, a Boolean one-hot vector of length four inserts the running hash at exactly one of four positions. The other three children are witness data. Their order feeds the 16-word parent sponge directly, preserving the released position-and-presorted-siblings relation. The active-depth bit selects the new parent or the old digest. Only a real slot must reach the funded tree root inside the header. The wallet sorts by the serialized digest when it constructs the path. [Native four-child path](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/merkle.rs)
* Native amounts and token quantities are each range-checked to 62 bits. Four private asset limbs are each bounded to 63 bits. Each positive token amount selects the same private ID; a zero amount selects a zero tag. The hidden ID is zero exactly when the total input token quantity is zero. Both token sums fit below 2⁶³. The native output sum plus the permitted fee is below p. Consequently the two conservation equations hold as integer equations.
* The native note opening incorporates the selected tag, token quantity and raw randomness. Each output rho is derived from **both** public nullifiers plus its output index. Both output commitments are recomputed and bound to their ordered public limbs. Each SLG1 output additionally hashes all eight range-checked authorization key words into its raw randomness before applying the common typed opening. The ordinary role can consequently spend the binding-preserving raw opening recovered by the existing recipient.
* As in the released native suite, the ordered pair of 1,792-byte receipts is hashed by the **public packet verifier** under the released `qnero/ct` codec. The proof transcript binds all public digest limbs. The four equality rows inside this frontend connect a private copy of that digest to the public statement. They do not prove encryption correctness or establish ownership of a receipt. Recipient opening, key-based commitment checking and actual later spending test those properties. Ancestor eligibility, replay prevention, branch state, fees and outer signatures likewise remain duties of the external verifier and ledger. [Released receipt digest](https://github.com/DigitalGuards/qnero/blob/f04c91307837c0231668383bec76ba98d89d2652/crates/qnero-circuit/src/chain.rs)

## Encoding and checks

`frontend.py register PROFILE CONSTANTS MATRIX` streams the verifier-owned public program. `CONSTANTS` must be the qp-poseidon-core 3.1.0 `src/poseidon2.rs` with SHA-256 `54604af022354364c45fbdde106be3f223775992d6fa5685e77c75e66fd970f6`. Each matrix starts with ASCII `FWHRCS01`, then u32LE public-column count excluding ONE, total columns including ONE, and row count. Each row consists of A, B and C affine forms. A form is a u32LE term count and that many ascending (u32LE column, canonical u64LE coefficient) pairs. The ordinary matrix occupies 15,245,888 bytes and the swap matrix occupies 15,637,808 bytes. The programming interface `assign(profile, Path(constants), private_witness)` creates the private integer vector in memory. `words_as_bytes` encodes its contiguous u64LE columns for the wallet's local WHIR prover. The command `frontend.py assign PROFILE CONSTANTS - -` connects the two private pipes. The CLI accepts pipes, sockets and inherited anonymous Linux memfd descriptors. It rejects regular disk files and terminals for private input or output.

The independent row reader in `controls.py` consumes the pinned serialized matrix and an assignment. The numeric reference builds deterministic synthetic funded-note paths and projections with a separate integer implementation of the permutation. Negative checks change a private opening, asset, amount, path, key or flag. For economic controls the reference also republishes the new commitments so a stale expected output cannot explain the rejection. Each full negative assignment is checked against the original matrix. To test a malicious auxiliary directly, the reader takes an otherwise honest assignment, changes one private height-decomposition bit to the field element 2, and checks the frozen rows without calling the witness builder. The same `check_funded` function accepts a genuine recovered wallet witness in protected memory, returning only booleans and the public matrix identity. Changing any public input encoding to p is rejected before field reduction. Both profiles also accept honest assignments at the largest supported u62 values and u63 asset limbs, with a u32 maximum height.

```sh
python3 -IB experiments/funded-whir/relation/frontend.py register MNG1 "$constants" "$work/MNG1.r1cs"
python3 -IB experiments/funded-whir/relation/frontend.py register SLG1 "$constants" "$work/SLG1.r1cs"
python3 -IB experiments/funded-whir/relation/controls.py MNG1 "$constants" "$work/MNG1.r1cs"
python3 -IB experiments/funded-whir/relation/controls.py SLG1 "$constants" "$work/SLG1.r1cs"
```

Both complete matrices need an 18-variable power-of-two row and column domain. Constraint satisfaction and matrix equivalence on private fixtures say nothing on their own about the proof system's Fiat–Shamir knowledge, hiding or joint quantum bounds.
