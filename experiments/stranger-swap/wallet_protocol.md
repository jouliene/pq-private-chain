# Private quotes and wallet consent

A discovered advertisement authenticates a maker's contact. The seller sends its receiving address, the token ID, the quantity it proposes to sell, a random request ID and an independent 32-byte bearer capability inside that maker's authenticated encrypted channel. Each independently requested quote uses fresh identifiers. The request has no maker receiving address or proposed price. The maker chooses the price from its operator's local policy. This implementation trades a positive, single-token quantity for native currency, with side A selling tokens and side B paying all 3 native units of the swap fee. [Negotiation implementation](negotiation.py) · [Private wallet operations](wallet_local.py)

The private quote contains exactly these fields. Canonical JSON uses ASCII, lexicographically sorted keys, decimal JSON integers, and separators comma and colon without whitespace. Byte strings are lowercase hexadecimal. All identifiers, the nonce and token ID occupy 32 bytes, while each receiving address occupies 1,601 bytes.

| Fields | Meaning |
|---|---|
| `version`, `advert`, `network` | Private format version 1, digest of the complete verified signed advertisement, and local consensus network. |
| `request`, `holder`, `quote`, `nonce` | Taker-generated request ID, SHA-256 of the taker's capability bytes, maker-generated quote handle, and independent maker-generated secret randomness. |
| `maker`, `taker` | Maker receiving address returned over the authenticated channel and taker's receiving address from its original request. |
| `asset`, `quantity`, `native`, `payer`, `fee` | Token ID and quantity delivered to B, native price delivered to A, payer `b`, fee 3. |
| `expires`, `expiry_height` | Exclusive Unix-seconds expiry for establishing consent and inclusive last eligible block height, respectively. Wall expiry cannot exceed advertisement expiry. |

The blind in the ordinary SWPTER02 private agreement is SHA-256 of `SSW1/firm-quote/v1`, one zero byte, and the entire canonical private quote. The public SWP1 digest commits to the salted private agreement, network, payer, height expiry and both ordered full leg hashes. Changing the maker, price, asset, address, request, capability, quote handle or deadline changes the agreed commitment. The private quote obtains its origin authentication from the live pinned channel. It has no detached maker-identity signature. The proof-bound final signatures use the existing per-swap SLH-DSA keys. ## Reserving, choosing and signing

1. The maker draws a quote handle and nonce, stores the immutable request and quote, and proves a native leg using its real spendable notes. The ordinary wallet outbox reserves these notes before any funded quote response. Insufficient funding generates a refusal. The successful response includes one genuine leg. The taker's spending-key role opens its primary receipt for the full native price and zero token, checks the native fee, verifies the proof and checks the branch anchor. The taker has made no offer and reserved no notes at this stage. It can compare multiple firm quotes.
2. The taker chooses the private handle and enters the exact asset, quantity, price and height deadline independently. A different price or currency is rejected before contacting the maker. Preparing the selected leg reserves the taker's actual token note and verifies the taker's change. An authenticated private status request checks that the maker is still reachable before the taker signs. The unchanged wallet's final authorization path verifies both complete proofs, both fees, own approved leg, incoming native receipt under actual spend keys, own change, eligible branch anchors, local inputs and expiry.
3. The taker durably stores its signature before sending its leg and signature to the selected maker. The maker validates the capability and quote handle, verifies the received leg, decrypts the exact token payment, and verifies the taker's signature on this particular pair. Its wallet then performs its own complete authorization checks before persisting the maker signature. An identical retry can retrieve this signature from the same authenticated endpoint and still-valid advert. The taker checks both proofs and signatures and forms the complete canonical bundle before public submission. The taker and maker never exchange seeds, spend witnesses, note inventories, change markers or per-swap signing secrets.
4. The public validating node checks both legs together, including actual spentness and branch eligibility. A previously valid quoted input can race a competing spend or go stale on a fork. A quote and a local signature are distinct from atomic consensus admission. [Original wallet policy](../atomic-swap/wallet/swap_wallet.py) · [Public atomic validation](../atomic-swap/swap_ledger.py)

For the accepted synthetic scenario, the seller's receipt must open to `(8 native, zero token, zero ID)` and the maker's to `(0 native, 20 tokens, expected managed ID)`. A recaptured native receipt and its derived nullifier supply the ordinary spend after seed recovery. Firm-quote handles, cap hashes, prices, full private quote records and addresses are kept out of relay advertisements and public block payloads. Each contacted maker learns the requested token/amount and the taker's address. Reusing that address across makers permits correlation by cooperating makers. Endpoint connection metadata, ciphertext sizes and timing remain observable.

## Durable state and ambiguous delivery

Private per-wallet files live at `HOME/stranger-private/WALLET/{maker,taker}/REQUEST_ID/`. They include `session.json`, `terms`, `peer.addr`, leg and signature files when applicable, and the fully verified taker `packet` after successful combination. The original wallet's private outbox remains authoritative for reserved commitments and signatures. The handler holds a local file lock, persists state with fsync and atomic rename, and reconciles interrupted signing against the wallet journal. Concurrent operations on a wallet's funding use the original wallet lock. A maker can have four active funded/in-progress quotes by default, configurable up to 16. A single signed advertisement permits at most 256 recorded requests per wallet role. Full transcripts grow with successive genuine advertisements and trades. A fresh empty store cannot independently resume an earlier off-chain authorization.

| Local state | Consequence |
|---|---|
| Maker `allocating` → `quoted` | Repeating the ordinary quote command after a lost first reply finds its outstanding request for that advert, wallet, asset and quantity and retries with the original capability. A definite refusal received from the authenticated maker closes the rejected request, allowing the ordinary command to begin a fresh one. An ambiguous channel failure keeps the original capability for retry. A failed proof with no reserved offer is declined. An unselected quote creates no on-chain payment. |
| Taker `quoted` → `prepared` | The taker has privately reserved its real inputs. `cancel --offline` releases this reservation even if the maker is unreachable. An attempted remote cancellation reports its separate result. |
| Taker `releasing` → `released` | The original wallet stores a signature over exactly one joint digest. Local cancellation refuses once signed. `delivery=none` is possible before network transmission. `attempted` means the peer may already have the signature, even after timeout. |
| Maker `signing` → `signed` | Both signatures are available on the maker. The same final request can recover the exact stored response. Withholding delivery remains possible. An altered leg or signature on a retry is refused. |
| Taker `complete` | Both proofs and signatures passed. The packet and its SHA-256 are recoverable for idempotent public submission. `acknowledged` refers to the completed private exchange. Node acknowledgment and confirmation are separate. |

`Maker.sweep()` checks wall time and the selected node's next height. Each new quote also triggers this check, and an expired status request rechecks the relevant quote. The sweep releases unsigned maker reservations through the ordinary wallet and preserves any existing authorization. A stopped maker cannot reap until restarted or another local maker instance sweeps that wallet. If an authorization was already delivered, a wall-clock timeout cannot revoke it. Consensus enforces the signed height deadline on the selected branch, and a reorganization can change eligibility. Losing the original pinned endpoint or advertisement may prevent retrieval of a withheld signature. The next operator can still inspect local private journals.
