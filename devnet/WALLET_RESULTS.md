# Ordinary wallet on the continuous local PoW devnet

**Decision.** Use the persistent APV2 wallet for ordinary balance, send and seed restore. Keep full scanning as a recovery reference and correctness oracle. The implementation descends from `82c803961996864782a5dee050a02b60b4341c0e`. Run `./pqd start` for the live network and `./pqd wallet-walkthrough` for a fresh measured acceptance run. ## What changed in a real payment

The author created an address and backed up the receiving seed, then removed the original disposable receiving wallet. A separate sender used only the exported address. We disconnected the sender before the first genuine submission could reach the node, let eight more real blocks arrive and verified the node rejected that old packet for anchor age. On resumption we dropped the reply **after** a node accepted the replacement. A new sender process connected to another validating peer and reconciled the intent from common selected history. One canonical packet paid 29 with fee 3 and change 68. The offline recipient's restored wallet opened that receipt and a separate 17-unit receipt, spent 37 from both inputs, paid 3 and retained 6. Public-only replay verified three separate authorizations for the 29-unit intent with a common nullifier. Exactly one occurred in the final selected chain. Decryption, input ownership and private balances were observed in the fresh wallet runs. [Author record](evidence/wallet-sync/author/WALLET.json) · [Public replay](evidence/wallet-sync/author/PUBLIC_REPLAY.json)

Seed restore was killed between pages while mining continued. The next process first requested block 17 of the original prefix, completed H46, then caught up to H47. A separate shallow fork removed one block and applied two replacements. On a twelve-block detach from H14 back to the fork at H2, the wallet's eight-deep undo history required replay from genesis to H45. The losing payment ceased to be confirmed; its input had been spent by a different payment on the winner. A new payment spent the winner's valid change. After each branch change the full-scan inventory, spending status, balances and each positive note's positional Merkle siblings agreed. Empty and funded wallets at the same H45 cursor sent identical history requests for H46. [Acceptance scenario](wallet_walkthrough.py)

## Measured history and wallet costs

The two controlled arms used **real PoW branches** with initial lengths of 4 and 40. The same seed held one 100-unit common-prefix reward. Each arm measured cold restore, an unchanged balance, one neutral-reward append followed by a balance, and another matching append followed by a new, complete 17-unit payment. The node accepted each proof; the next mined block included it. Fixed tips separated size effects from the random miner clock. The continuous-miner fault and spending experiments used the same normal CLI in separate stages.

The unchanged response performs two small metadata reads (216 logical B) and the CLI exchanges 1,698 / 2,066 total framing and metadata bytes at H4/H40. Each warm send uploaded one full 230,206-byte singleton in addition to synchronization. Proof plus setup used about 25 native CPU-s on the author's i7-8700K. The native prover high-water RSS was about 1.04 GiB. The CLI columns report wall time around a fresh command and GNU time's RSS observation. The proof runs inside a distinct isolated process; the 30 MiB CLI measurement alone misses that cost. Native wallet figures use the higher of the sync worker's observed high-water mark and its internal operation meters. The separate native hash helper, invocation framing, CPU observations, frontier/path and SQLite file sizes are available in the per-operation record. Individual process peaks need not occur simultaneously.

## Node costs and retained limits

A preliminary header query on a wide SQLite primary B-tree caused hundreds of kilobytes of database-file reads for tiny metadata-only replies. The public endpoint now uses a covering metadata index and a small mapping to separately stored projected bodies. On the tested old node database the one-time history migration inspected 25 previously admitted blocks, 926,390 complete archived bytes and four proofs, and wrote 22,601 bytes of projection payload. This startup cost is separate from ordinary requests. The independent syscall measurements distinguish logical SQLite values, file bytes read into SQLite (which may be satisfied by the OS cache), and physical device activity. Validating a submitted proof, checking current ledger state and storing it in a mempool are additional node operations. [Migration and query plans](evidence/wallet-sync/NODE_HISTORY_CHECK.json) · [Independent file and admission probes](wallet-review/REVIEW.md)

The non-author rebuilt revision `2b6ae99f4f91135ef5974b69fbef987357336711` and ran fresh wallets and miners. The independent warm sends took 14.04 / 13.87 s at H4/H40, and native high-water RSS was 1,090,572 / 1,090,924 KiB. A fresh public verifier accepted all 115 captured PoW blocks and all three sender authorizations and found exactly one selected payment for that intent. The recipient used 46 to pay 37, with fee 3 and change 6. The original capture ended one block after that spend. A separately mined and verified second successor retained it. The final walkthrough requires two successors before ending. A later correction binds input reservations and the first transmissible packet in the same database transaction. Tests with a noncanonical recipient and real SQLite transaction failures checked that proof or persistence failure leaves unexposed funds available. A warm unchanged query on each real history caused one 16-byte SQLite file read. A newly opened SQLite connection at the same two heights read 8,208 / 12,304 bytes; index lookup and cache state affect those counts. After a single empty append the repeated range request used 46 SQLite VM steps at either size. A repeated one-payment range read 3,616 main-file bytes at both. Separately, submitting a valid 230,206-byte packet at H6/H42 caused 20,496 / 24,592 main-file read bytes, 0 / 4,096 process-charged physical input bytes and 262,144 charged write bytes in both arms. Traced end-to-end node admission took 21.22 / 21.53 ms. Each measurement labels the operation, cache and role. The wallet stores its own notes and paths. The frontier grows with tree depth, updating witnesses costs work proportional to funded outputs appended and live owned paths, and selection depends on live unspent holdings. Sender reservations and observed attempt IDs consume private storage. Keeping a trusted validating node, having the selected history available and preserving the sender outbox for ambiguous undelivered intents remain operational assumptions. The original fee, block, proof and fork-choice checks remain active. At 100M inclusions/year complete payment packets still project to 23.0206 decimal TB per archival copy before block framing and indexes. End-to-end PQ/privacy, network anonymity, production economics, private assets and atomic swaps remain on the global roadmap.
