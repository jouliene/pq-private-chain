# Ordinary APV2 wallet synchronization and payment intents

The local PoW wallet uses the payment relation, note format, fee and fork choice from the [first devnet](CONSENSUS.md). The wallet's selected local validating node checks complete PoW blocks and payment proofs. The wallet authenticates its funded tree and maintains private membership paths. A compact history projection omits full proofs and mining preimages; association of transaction IDs and completeness of encrypted receipt data rely on the selected node. The design uses the CP03 continuation principles of a wallet-owned base, common ranges, exact endpoints, retained joint checkpoints and atomic promotion. APV2 requires its own sorted quaternary membership paths, header encoding and note receiver.

## Public wire and storage

`history_head` takes a bounded list of locally committed height/block IDs down to genesis. The server returns its current selected chain/network, common point and terminal descriptor. `history_range(target,start,base,limit)` checks a still-selected fixed target and base in a single database transaction and seeks directly to the requested heights. Each binary reply contains at most 16 complete projected blocks. A 9-byte range prefix precedes a 305-byte record per block and 3,744 bytes per ordinary payment. Each payment contributes its transaction ID, two nullifiers and two ordered commitment/ciphertext pairs. One 104-byte public reward row occurs in each block. `history_check(target)` establishes that a captured prefix is still selected while allowing later appends. Requests depend on chain position, never note positions, funding keys, nullifiers or subtrees.

The node writes the projection alongside admission of each full accepted block, including stored side branches. A legacy database undergoes a one-time transactional backfill on startup. Header reads use a covering index; the narrow block ID index for projection lookup refers to a separate rowid payload. These choices keep large proof/receipt blobs outside the lookup keys. Logical record reads, SQLite file reads through the OS cache, and physical-device traffic measure different things.

## Private cursor and recovery

A wallet directory holds its protected 32-byte seed, operation lock, SQLite sync state and SQLite intent journal. The sync database binds its owner, network, genesis, retained height/block IDs and complete AP headers to the tree count/frontier, accounting and owned notes. Only the current right edge of the tree and the actual local spending paths are necessary when the next leaves arrive. Each append updates the affected sibling position in a live path; growing the depth adds a level. Native APV2 hashing and recipient opening determine the funded root and locally owned notes. The proof builder consumes the exact privately reconstructed path and invokes the same registered payment circuit.

A page transaction updates the cursor, frontier, notes, spent dates, local balances, paths and related canonical transaction identities together. Captured target height/ID, header, note count and anchor persist across interruption. A reopened wallet resumes from its committed page boundary and completes that fixed selected prefix. A bounded follow-up samples a newer head for catch-up. When mining continues, every reported balance refers to the displayed cursor. If a target leaves the selected branch, the wallet reconciles with its own retained checkpoints. The eight-block undo window supports incremental reversal; older divergence causes full selected-history replay. Memory and local write costs grow with live owned notes, tree depth and journal retention. Wallet history inspection and the full-tree oracle are outside ordinary synchronization.

## Offline recipient and sender outbox

The portable address file is `PQDADDR1 || network_id || 1601-byte address || SHA256(preceding bytes)`. It contains the public spending identifier and ML-KEM-1024 encapsulation key. The checksum detects transmission errors. The recipient's private keys remain with the recipient. The sender constructs encrypted receipts and change locally; validators receive the complete APV2 singleton.

Before network exposure the sender durably binds its local intent ID to recipient bytes and amount, reserves one or two exact real note commitments, and commits the complete candidate packet and its SHA-256 transaction ID. Each replacement consumes the same reserved real inputs. Their nullifiers enforce mutual exclusion on every valid selected chain, including when old and new packets reach different peers. Each retry checks the whole attempt-ID list against wallet-related transactions on its current selected history. An absent reply leaves the packet available for replay. A change of selected branch invalidates stale confirmation. An unknown spender or missing funding leaves the intent unresolved. A positive mempool acknowledgement is evidence of receipt by that node; selected inclusion is checked independently. Retaining a sender's journal is essential to recover its off-chain intent after a crash. An independently restored copy of the seed reconstructs on-chain funds and has a separate outbox.

## Scope

The measured wallet handles paid occupancy and isolated synthetic participants on one Linux host. Archive nodes still store complete payment proofs and full block bodies, including known side branches. At 100M included APV2 payments/year the 230,206-byte packets alone project to 23.0206 decimal TB per first archival copy. The new common history projection adds data and indexes on serving nodes. Cold wallets need access to selected public history. Traffic metadata, privacy of mining rewards, general network availability, production PoW economics and noninteractive end-to-end PQ/privacy arguments remain open. Private asset transfer with native fees and atomic two-owner swaps retain their previous versioned design path.
